Vue 3 slots 源码解析：插槽为什么是函数

发表于2026|更新于2026|Vue框架及周边库
|字数总计:1.6k|阅读时长:6分钟

源码说明：本文分析的源码基于 vue@3.5.21，对应官方仓库为 vuejs/core，本文所在学习仓库为 XY0987/vue_ori_learning。

前言：组件通信里，props 是父传子，emit 是子通知父，slots 则是父组件把一段渲染逻辑交给子组件。Vue 3 里 slot 的核心形态是函数，这不是偶然设计，而是为了让插槽内容的执行时机、依赖收集和更新边界更清晰。

先给结论

slot 可以简单理解成：

父组件提供一段函数
子组件在合适的位置调用这个函数
函数返回 VNode 数组

也就是说：

<Child>
  <div>{{ msg }}</div>
</Child>

在运行时更接近：

h(Child, null, {
  default: () => [h('div', msg)],
})

为什么要做成函数？我的理解主要有三点：

原因 说明
延迟执行 子组件决定什么时候渲染 slot
正确收集依赖 slot 内容在 render 阶段执行，里面用到的响应式数据才能被正确追踪
优化更新 编译器可以标记 stable / dynamic slots，运行时少做无效更新

编译器如何生成 slots 对象

v-slot 不是普通指令转换，它会在 transformElement 里调用 buildSlots：

// Instead of being a DirectiveTransform, v-slot processing is called during
// transformElement to build the slots object for a component.
export function buildSlots(
  node: ElementNode,
  context: TransformContext,
  buildSlotFn: SlotFnBuilder = buildClientSlotFn,
): {
  slots: SlotsExpression
  hasDynamicSlots: boolean
} {
  context.helper(WITH_CTX)

  const { children, loc } = node
  const slotsProperties: Property[] = []
  const dynamicSlots: (ConditionalExpression | CallExpression)[] = []

  // If the slot is inside a v-for or another v-slot, force it to be dynamic
  // since it likely uses a scope variable.
  let hasDynamicSlots = context.scopes.vSlot > 0 || context.scopes.vFor > 0

  // 1. Check for slot with slotProps on component itself.
  //    <Comp v-slot="{ prop }"/>
  const onComponentSlot = findDir(node, 'slot', true)
  if (onComponentSlot) {
    const { arg, exp } = onComponentSlot
    if (arg && !isStaticExp(arg)) {
      hasDynamicSlots = true
    }
    slotsProperties.push(
      createObjectProperty(
        arg || createSimpleExpression('default', true),
        buildSlotFn(exp, undefined, children, loc),
      ),
    )
  }

这说明编译器做了两件事：

  1. 把 slot 内容包装成函数。
  2. 判断 slot 是稳定的还是动态的。

比如：

<Child>
  <template #default="{ item }">
    <span>{{ item.name }}</span>
  </template>
</Child>

会生成类似：

{
  default: withCtx(({ item }) => [
    createElementVNode('span', null, item.name)
  ]),
  _: SlotFlags.STABLE
}

这里的 withCtx 用来绑定 slot 的渲染上下文，避免 slot 函数在错误的组件上下文里执行。

SlotFlags：稳定插槽和动态插槽

buildSlots 最后会给 slots 对象打标记：

const slotFlag = hasDynamicSlots
  ? SlotFlags.DYNAMIC
  : hasForwardedSlots(node.children)
    ? SlotFlags.FORWARDED
    : SlotFlags.STABLE
let slots = createObjectExpression(
  slotsProperties.concat(
    createObjectProperty(
      `_`,
      // 2 = compiled but dynamic = can skip normalization, but must run diff
      // 1 = compiled and static = can skip normalization AND diff as optimized
      createSimpleExpression(
        slotFlag + (__DEV__ ? ` /* ${slotFlagsText[slotFlag]} */` : ``),
        false,
      ),
    ),
  ),
  loc,
) as SlotsExpression
if (dynamicSlots.length) {
  slots = createCallExpression(context.helper(CREATE_SLOTS), [
    slots,
    createArrayExpression(dynamicSlots),
  ]) as SlotsExpression

可以这样理解：

SlotFlags 含义
STABLE 插槽结构稳定，运行时可以跳过一些更新
DYNAMIC 插槽受 v-if、v-for、动态名称等影响，需要更新
FORWARDED 插槽从父组件继续转发，稳定性取决于来源

这也是编译器和运行时协作的一个例子：编译器提前判断 slot 的稳定性，运行时根据标记决定是否要更新。

initSlots：组件实例如何接收 slots

组件实例初始化时会调用 initSlots：

export const initSlots = (
  instance: ComponentInternalInstance,
  children: VNodeNormalizedChildren,
  optimized: boolean,
): void => {
  const slots = (instance.slots = createInternalObject())
  if (instance.vnode.shapeFlag & ShapeFlags.SLOTS_CHILDREN) {
    const type = (children as RawSlots)._
    if (type) {
      assignSlots(slots, children as Slots, optimized)
      // make compiler marker non-enumerable
      if (optimized) {
        def(slots, '_', type, true)
      }
    } else {
      normalizeObjectSlots(children as RawSlots, slots, instance)
    }
  } else if (children) {
    normalizeVNodeSlots(instance, children)
  }
}

这里可以看到，slot 最终会放到：

instance.slots

如果是编译器生成的 slots，里面已经有 _ 标记，可以直接 assignSlots。如果是手写 render 传进来的普通对象，就需要 normalize。

为什么非函数 slot 会被包成函数

运行时也会把非函数 slot 包成函数：

const normalizeObjectSlots = (
  rawSlots: RawSlots,
  slots: InternalSlots,
  instance: ComponentInternalInstance,
) => {
  const ctx = rawSlots._ctx
  for (const key in rawSlots) {
    if (isInternalKey(key)) continue
    const value = rawSlots[key]
    if (isFunction(value)) {
      slots[key] = normalizeSlot(key, value, ctx)
    } else if (value != null) {
      if (__DEV__) {
        warn(
          `Non-function value encountered for slot "${key}". ` +
            `Prefer function slots for better performance.`,
        )
      }
      const normalized = normalizeSlotValue(value)
      slots[key] = () => normalized
    }
  }
}

这段代码很直接：Vue 仍然兼容非函数 slot，但开发环境会提示：推荐使用函数 slot。

原因还是那句话：slot 本质上是“可延迟执行的渲染逻辑”。函数形式才能让执行时机由子组件控制。

renderSlot：子组件如何渲染插槽

子组件模板里写：

<slot name="header" :title="title" />

编译后会调用 renderSlot。运行时入口是：

export function renderSlot(
  slots: Slots,
  name: string,
  props: Data = {},
  // this is not a user-facing function, so the fallback is always generated by
  // the compiler and guaranteed to be a function returning an array
  fallback?: () => VNodeArrayChildren,
  noSlotted?: boolean,
): VNode {

核心是取出对应 slot 函数并执行：

let slot = slots[name]

openBlock()
const validSlotContent = slot && ensureValidVNode(slot(props))
const slotKey =
  props.key ||
  // slot content array of a dynamic conditional slot may have a branch
  // key attached in the `createSlots` helper, respect that
  (validSlotContent && (validSlotContent as any).key)
const rendered = createBlock(
  Fragment,
  {
    key:
      (slotKey && !isSymbol(slotKey) ? slotKey : `_${name}`) +
      (!validSlotContent && fallback ? '_fb' : ''),
  },
  validSlotContent || (fallback ? fallback() : []),
  validSlotContent && (slots as RawSlots)._ === SlotFlags.STABLE
    ? PatchFlags.STABLE_FRAGMENT
    : PatchFlags.BAIL,
)

这说明 <slot/> 最终不是特殊魔法，而是：

从 instance.slots 取函数
传入 slot props
执行函数得到 VNode
包成 Fragment 返回

为什么 slot 是函数

我觉得可以用一句话概括：

slot 是父组件传给子组件的一段渲染函数，子组件负责决定调用位置和调用时机。

这带来几个好处：

  1. 子组件可以在自己的 render 过程中调用 slot。
  2. slot props 可以作为函数参数传回父级内容。
  3. slot 内部响应式依赖能在正确 render 上下文中被追踪。
  4. 编译器可以给 stable / dynamic slot 打标记，运行时减少无效更新。

小结

  1. Vue 3 中 slot 的核心形态是函数，函数返回 VNode 数组。
  2. 编译器会通过 buildSlots 把模板插槽编译成 slots 对象。
  3. SlotFlags 用来标记插槽稳定性，帮助运行时优化更新。
  4. 组件实例通过 initSlots 把 slots 保存到 instance.slots。
  5. 子组件渲染 <slot/> 时，本质是调用 renderSlot，执行对应 slot 函数。
