《Vite：从使用到精通》：我写的一个三阶段递进的 Vite 系列

发表于2026|更新于2026|工程化
|字数总计:2.4k|阅读时长:7分钟

前言：这篇不是技术教程，而是一篇”安利”。前段时间我写了一个 Vite 系列小册《Vite：从使用到精通》，沿「使用 → 源码 → 哲学」三阶段递进。这篇把它写了什么、为什么现在写、适合谁读讲清楚，感兴趣的可以直接去看：https://github.com/XY0987/vite_brochure_public。文中涉及的版本节点变化很快，具体请以各项目官方文档为准。

为什么在 AI 时代还要写一本 Vite 小册

先说我最纠结的一点：现在 AI 能随手给你一份能跑的 vite.config，那还写这东西干嘛？

我的答案是：AI 能给配置，但有三件事它替代不了。

  • 理解配置背后的取舍——为什么这么配、代价是什么
  • 出问题时的定位能力——报错日志背后到底发生了什么
  • 版本迁移时的工程判断——这个升级值不值得做、风险在哪

这三件事恰好是前端工程化的基本功，也正是 AI 的能力边界。所以这本小册干脆不做”配置速查”（那正是 AI 最擅长、也最没必要由人来写的部分），而是聚焦 AI 替代不了的地方：源码级的实现理解 + 版本演进背后的工程决策 + 可迁移的设计思想。

我的判断是：AI 时代，这类内容不是过时，反而更有必要。

还有一个更直接的动因——时机。Vite 8 + Rolldown 是 Vite 这几年最大的一次架构变更：dev 和 build 从过去的”双引擎”走向 Rust 单打包器。而市面上多数 Vite 小册还停在 4/5，没覆盖 Environment API、Rolldown、Oxc 这条主线。这块空白正好值得补。

先用一张表把版本主线摆出来（事实基线为 2026 年中，以官方为准）：

版本 时间 核心变化
Vite 5 2023 底 esbuild(dev) + Rollup(build) 双引擎，企业现役主力
Vite 6 2024.11 Environment API；多环境模型；大规模内部重构但向后兼容
Vite 7 2025.06 清理废弃特性、rolldown-vite drop-in、Node 20.19+/22.12+
Vite 8 2026.03 Rolldown 成为默认唯一 Rust 打包器，dev/build 统一，Oxc 接管转译/压缩

这里有两条独立的演进主线容易被混为一谈，我在小册里是分开讲的：一条是架构抽象（Environment API，Vite 6 引入），另一条是打包器替换（Rolldown，Vite 7 引入、Vite 8 默认）。看懂这两条线，版本升级这件事就不慌了。

内容结构：三阶段递进

整本书的骨架就一句话——沿「使用 → 源码 → 哲学」往上走。每个阶段用一句话锚定边界，避免内容重叠：

阶段 回答的问题 读完你能做到
使用 怎么用、用哪个版本、配哪个工具 在真实项目里独当一面
源码 它内部怎么实现的 亲手 clone、打断点、跟真实流程
哲学 它为什么这么设计 把经验抽象成可迁移的判断框架

三个阶段难度逐级抬升，但彼此独立：可以从头入门，也可以直接跳到你需要的那一阶段。

第一阶段 · 使用（目标是用到精通，不是拉齐基线）

这一阶段的验收标准很朴素：**读完真的会用，而不是”读完仍不会用”**。所以它不止讲”怎么配”，还包含大量真实工程排障。覆盖的模块包括：

  • 核心使用：项目搭建、vite.config 完整配置、dev server / 构建 / 预览、依赖预构建、SSR / 库模式 / 多页应用、TypeScript 处理
  • 框架集成与测试：Vue / React / Svelte 接入机制、@vitejs/plugin-react 用 Oxc 接管 React Refresh、Vitest 原生测试
  • 插件与生态：从最小插件到完整生命周期钩子、Rollup 钩子模型与 Vite 的关系
  • 多环境与工程化：Environment API 落地、monorepo / workspace 组织、SSR 工程坑位、CI 集成与构建缓存
  • 版本差异与升级迁移：各版本迁移要点（如 rollupOptions → rolldownOptions、manualChunks → codeSplitting）、从 webpack / CRA / Vue CLI 迁移到 Vite 8 的实战
  • 打包工具横向对比：esbuild / Rollup / Rolldown / webpack / Oxc 各自定位与选型指南
  • AI 辅助 Vite 开发：怎么让 AI 生成可维护的配置、怎么借助 AI 排查报错、以及 AI 容易误导的场景

每个使用知识点都配了最小可运行 demo，专门为了兑现”读完真的会用”这句话。

第二阶段 · 源码（我的做法是”调源码”，不是”读源码”）

这是我个人最看重、也最花时间的一部分。我一直觉得，看源码截图学不到东西——真正有用的是亲手把它跑起来、打上断点、跟一遍真实流程。

所以源码篇的每条主线都是同一个节奏：① 亲手调试（clone、断点、跟真实流程）→ ② 梳理实现（抽象成机制图）→ ③ 小结（这段实现解决了什么、代价是什么）。

调试基线用最新的 Vite 8 源码。这里有个关键事实要澄清：Vite 自身的核心机制（dev server、HMR、插件容器、依赖预构建、模块图）至今仍是 TypeScript 实现，可以直接在最新源码上断点跟踪；Rolldown / Oxc 这些 Rust 工具链，我用架构与边界的视角讲清，并给出 Rust 侧的调试 / 日志切入点，不强求逐行啃 Rust。

覆盖的主线包括：配置加载与归一化、插件注册与排序、依赖预构建、按需编译与 dev server 请求处理（串起 resolveId → load → transform）、核心转换链路、插件容器（PluginContainer）、HMR 完整链路、模块图与依赖追踪、Environment API 的实现、以及 Vite 8 如何驱动 Rolldown 产出生产包。

还有一个专题专门讲底层引擎的历史与代价，其中 Rollup 与 Rolldown 的对比我做成了一张表：

维度 Rollup Rolldown
实现语言 JavaScript Rust
定位 生产构建打包器 统一 dev + build 的单一打包器
速度 基准 构建快约 10–30x
插件生态 原生 兼容 Rollup 插件 API（依赖内部实现的可能失效）
在 Vite 中 Vite 2–7 的 build 引擎 Vite 8 默认唯一引擎

第三阶段 · 哲学（把经验抽象成可迁移的判断框架）

最后一阶段是”务虚”的，但我给自己立了条硬规矩：每个设计思想都必须绑定前两阶段的具体案例，绝不脱离 Vite 空谈工程思想。

比如：

  • 复杂度的管理——dev 不打包 vs build 打包，本质是在”开发体验”和”生产产物”之间做持续权衡
  • 抽象的代价与收益——插件容器复用 Rollup 生态，既带来兼容性，也带来约束
  • 架构决策的时机——双引擎 → 单引擎，为什么是现在而不是更早或更晚
  • 渐进式演进——Environment API 如何在大规模重构中保持向后兼容
  • AI 时代的工程判断——AI 能生成配置、能解释源码，但最终还是要靠最小复现、源码断点、版本事实和产物验证来建立确定性

目标是：忘掉具体实现之后，你还能带走一套评估其他框架 / 工具的方法论。

凭什么是这一本

掘金上 Vite 小册不止一本，我自己也参考过。这本的区隔点主要是四条：

  1. 时效性最新——内容覆盖到 Vite 8 + Rolldown 这条最新主线，而非停留在 Vite 4/5
  2. 调试驱动——源码部分配套可调试的 Vite 源码分支与断点配置，读者亲手跟真实流程，而不是被动看代码贴图
  3. 三阶段闭环——多数小册只做一头（要么纯使用、要么纯源码），这本打通了”使用 → 源码 → 哲学”完整链路
  4. 决策视角——用 Environment API / Rolldown 这两条主线梳理版本演进，直接服务企业升级与选型判断

适合谁读

三阶段是阶梯式设计，覆盖从入门到资深的连续光谱：

读者 诉求 主要阶段
入门 / 在用 把 Vite 在项目中用到精通 第一阶段
进阶 从”会配置”到”懂原理、能调源码” 第二阶段
资深 / 决策 沉淀可迁移设计思想、做选型决策 第三阶段

前置要求不高：熟悉 JavaScript/TypeScript、ES Module、基本的 Node.js 与前端构建概念就行（第一阶段会照顾基础）。

在哪看

主仓库（大纲、章节文稿）在这里：https://github.com/XY0987/vite_brochure_public

另外还有两个配套仓库，方便读者一边看一边动手：

  • 使用篇配套代码：每个知识点的最小可运行 demo，按章节目录组织
  • 源码篇调试仓库：fork 的可调试 Vite 8 源码分支 + VS Code 断点 / launch 配置，可一键复现书中的调试路径

感兴趣的话，从第一阶段的 README 开始翻就行，也欢迎提 issue 交流。

小结

  1. 这是一个沿「使用 → 源码 → 哲学」三阶段递进的 Vite 系列，目标是把读者从”会用”带到”精通原理”，再到”理解设计思想”。
  2. 之所以在 AI 时代写它，是因为聚焦的正是 AI 替代不了的取舍理解、问题定位和迁移判断。
  3. 内容覆盖到 Vite 8 + Rolldown 这条最新主线，补上了多数小册停在 4/5 的空白。
  4. 源码部分坚持”调源码”而非”读源码”，每条主线都能亲手断点复现。
  5. 三阶段独立可入，入门到资深都能各取所需，仓库地址：https://github.com/XY0987/vite_brochure_public。
