Vue 3 指令 transform 源码解析：v-if、v-for、v-model 如何变成 render 代码

发表于2026|更新于2026|Vue框架及周边库
|字数总计:1.5k|阅读时长:6分钟

源码说明：本文分析的源码基于 vue@3.5.21，对应官方仓库为 vuejs/core，本文所在学习仓库为 XY0987/vue_ori_learning。

前言：模板中的 v-if、v-for、v-model 看起来都是指令，但它们在编译器中的处理方式并不相同。v-if 和 v-for 会改变 AST 结构，属于结构化指令；v-model 更多是生成 props，属于指令转换。

transform 预设中的顺序

编译器在 getBaseTransformPreset 中定义核心 transform 顺序：

export function getBaseTransformPreset(prefixIdentifiers?: boolean): TransformPreset {
  return [
    [
      transformOnce,
      transformIf,
      transformMemo,
      transformFor,
      transformExpression,
      transformSlotOutlet,
      transformElement,
      trackSlotScopes,
      transformText,
    ],
    {
      on: transformOn,
      bind: transformBind,
      model: transformModel,
    },
  ]
}

顺序很重要：

  • v-if / v-for 要先改写 AST 结构。
  • transformElement 要在结构稳定后生成 VNode call。
  • v-model 作为 directive transform，在元素处理阶段被转换为 props。

结构化指令是什么

普通指令通常只影响 props，例如 v-bind、v-on。结构化指令会改变节点本身：

指令 原始节点 转换后
v-if ElementNode IfNode，内部有多个 IfBranchNode
v-for ElementNode ForNode，内部保存 source / aliases / children
v-model DirectiveNode props：modelValue + onUpdate:modelValue

v-if 和 v-for 都通过 createStructuralDirectiveTransform 创建 transform，这意味着它们会先从 props 中移除对应指令，再替换或重组当前节点。

v-if：从节点变成分支链

入口：

export const transformIf: NodeTransform = createStructuralDirectiveTransform(
  /^(?:if|else|else-if)$/,
  (node, dir, context) => {
    return processIf(node, dir, context, (ifNode, branch, isRoot) => {
      return () => {
        if (isRoot) {
          ifNode.codegenNode = createCodegenNodeForBranch(branch, key, context)
        } else {
          const parentCondition = getParentCondition(ifNode.codegenNode!)
          parentCondition.alternate = createCodegenNodeForBranch(branch, key + ifNode.branches.length - 1, context)
        }
      }
    })
  },
)

v-if 的转换分两层：

  1. processIf 负责构建 AST：把 ElementNode 替换为 IfNode，把 v-else-if / v-else 合并到同一个分支链。
  2. createCodegenNodeForBranch 负责生成代码结构：条件表达式、注释占位符、分支 VNode。

v-else 如何找到 v-if

v-else 不能单独存在，它需要向前找到相邻的 v-if：

} else {
  const siblings = context.parent!.children
  const comments = []
  let i = siblings.indexOf(node)
  while (i-- >= -1) {
    const sibling = siblings[i]
    if (sibling && sibling.type === NodeTypes.COMMENT) {
      context.removeNode(sibling)
      __DEV__ && comments.unshift(sibling)
      continue
    }
    if (sibling && sibling.type === NodeTypes.TEXT && !sibling.content.trim().length) {
      context.removeNode(sibling)
      continue
    }
    if (sibling && sibling.type === NodeTypes.IF) {
      context.removeNode()
      const branch = createIfBranch(node, dir)
      sibling.branches.push(branch)
      traverseNode(branch, context)
      context.currentNode = null
    }
    break
  }
}

这里有几个细节：

  • 空白文本会被移除，因为它不应该阻断 v-if / v-else 的相邻关系。
  • 开发环境下的注释可能被临时收集并放回分支中。
  • v-else 节点被移除后，需要手动 traverseNode(branch, context)，否则它的子节点不会继续被转换。

为什么 v-if 分支要注入 key

function createChildrenCodegenNode(branch, keyIndex, context) {
  const keyProperty = createObjectProperty(
    `key`,
    createSimpleExpression(`${keyIndex}`, false, locStub, ConstantTypes.CAN_CACHE),
  )
  // ...
  injectProp(vnodeCall, keyProperty, context)
}

不同分支可能生成相同类型的 DOM。如果没有分支 key，运行时可能错误复用旧分支的 DOM。编译器自动注入 key，是为了告诉 runtime：这些分支虽然位置相同，但身份不同。

v-for：从循环表达式到 Fragment block

入口：

export const transformFor: NodeTransform = createStructuralDirectiveTransform(
  'for',
  (node, dir, context) => {
    const { helper, removeHelper } = context
    return processFor(node, dir, context, forNode => {
      const renderExp = createCallExpression(helper(RENDER_LIST), [forNode.source])
      const isTemplate = isTemplateNode(node)
      const keyProp = findProp(node, `key`, false, true)
      const keyProperty = keyProp && keyExp ? createObjectProperty(`key`, keyExp) : null
    })
  },
)

v-for 最终会生成类似这样的 render 结构：

(openBlock(true), createElementBlock(Fragment, null, renderList(list, item => {
  return (openBlock(), createElementBlock('div', { key: item.id }, item.name))
}), 128 /* KEYED_FRAGMENT */))

fragmentFlag 决定运行时 children diff 路径

const isStableFragment =
  forNode.source.type === NodeTypes.SIMPLE_EXPRESSION &&
  forNode.source.constType > ConstantTypes.NOT_CONSTANT
const fragmentFlag = isStableFragment
  ? PatchFlags.STABLE_FRAGMENT
  : keyProp
    ? PatchFlags.KEYED_FRAGMENT
    : PatchFlags.UNKEYED_FRAGMENT

forNode.codegenNode = createVNodeCall(
  context,
  helper(FRAGMENT),
  undefined,
  renderExp,
  fragmentFlag,
  undefined,
  undefined,
  true /* isBlock */,
  !isStableFragment /* disableTracking */,
)

这段代码把编译期判断传给运行时：

编译结果 运行时行为
STABLE_FRAGMENT 顺序稳定，走 block children 优化
KEYED_FRAGMENT 进入 patchKeyedChildren
UNKEYED_FRAGMENT 进入 patchUnkeyedChildren

这就是为什么 v-for 是否写 key 会影响运行时 diff 策略。

为什么 v-for 的子节点在退出阶段处理

return () => {
  let childBlock: BlockCodegenNode
  const { children } = forNode
  const needFragmentWrapper = children.length !== 1 || children[0].type !== NodeTypes.ELEMENT

  if (needFragmentWrapper) {
    childBlock = createVNodeCall(context, helper(FRAGMENT), keyProperty ? createObjectExpression([keyProperty]) : undefined, node.children, PatchFlags.STABLE_FRAGMENT, ...)
  } else {
    childBlock = (children[0] as PlainElementNode).codegenNode as VNodeCall
    childBlock.isBlock = !isStableFragment
  }

  renderExp.arguments.push(createFunctionExpression(createForLoopParams(forNode.parseResult), childBlock, true))
}

进入阶段只能知道“这是一个循环”，但还不知道循环体内部会生成什么。只有子节点都完成转换后，才能决定：

  • 循环体是否需要 Fragment 包裹。
  • key 应该注入到哪里。
  • 子节点应该是 block 还是普通 vnode。

v-model：编译成 prop + update 事件

入口：

export const transformModel: DirectiveTransform = (dir, node, context) => {
  const { exp, arg } = dir
  const rawExp = exp.loc.source.trim()
  const propName = arg ? arg : createSimpleExpression('modelValue', true)
  const eventName = arg
    ? isStaticExp(arg)
      ? `onUpdate:${camelize(arg.content)}`
      : createCompoundExpression(['"onUpdate:" + ', arg])
    : `onUpdate:modelValue`
}

所以：

<MyInput v-model="title" />

会变成：

createVNode(MyInput, {
  modelValue: title,
  "onUpdate:modelValue": $event => (title = $event)
})

如果写了参数：

<MyInput v-model:name="name" />

则变成：

createVNode(MyInput, {
  name,
  "onUpdate:name": $event => (name = $event)
})

script setup 中的 ref 特殊处理

let assignmentExp: ExpressionNode
const eventArg = context.isTS ? `($event: any)` : `$event`
if (maybeRef) {
  if (bindingType === BindingTypes.SETUP_REF) {
    assignmentExp = createCompoundExpression([
      `${eventArg} => ((`,
      createSimpleExpression(rawExp, false, exp.loc),
      `).value = $event)`,
    ])
  }
} else {
  assignmentExp = createCompoundExpression([`${eventArg} => ((`, exp, `) = $event)`])
}

如果模板里的变量来自 <script setup>，编译器会根据 binding metadata 判断它是不是 ref：

  • 明确是 ref：写入 .value。
  • 可能是 ref：运行时用 isRef() 判断。
  • 普通变量：直接赋值。

这也是 compileScript 和 template transform 之间协作的一个例子。

三个指令的对比

指令 主要源码 转换结果 运行时影响
v-if vIf.ts IfNode + 条件表达式 分支切换、注释占位、分支 key
v-for vFor.ts ForNode + renderList + Fragment keyed / unkeyed / stable diff
v-model vModel.ts props + update 事件 双向绑定、组件 modifiers、表单指令

小结

Vue 3 的指令 transform 可以从两个角度理解：

  1. 会改变 AST 结构的，是结构化指令，例如 v-if 和 v-for。
  2. 只生成 props 或 runtime helper 的，是普通指令转换，例如 v-model。

理解这些转换后，再看生成的 render 函数会清晰很多：模板语法本身并不直接运行，真正运行的是编译器生成的 VNode 创建代码。
