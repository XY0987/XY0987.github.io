DeepSeek Harness 开源：一切皆插件的 Agent 运行框架

发表于2026|更新于2026|AI相关
|字数总计:4.6k|阅读时长:15分钟

前言：2026-08-13 晚上，DeepSeek 正式开源了自己的 Agent 运行框架 DeepSeek Harness（CLI 叫 dsh），MIT 协议，开发者预览版。一个做基础模型出身的公司，亲自下场开源一套 Harness，这件事非常值得说道说道。

行业时间线

时间 事件
2026-02-25 Nous Research 开源 Hermes Agent，主打 Learning Loop + Skills 自我沉淀
2026-07 Anthropic 升级 Claude 5，把 Claude Code 的 System Prompt 砍掉 80%（unhobbling）
2026-08-13 DeepSeek 开源 DeepSeek Harness（dsh）开发者预览版 v0.1，MIT 协议
2026-08-14 内测两周社区贡献插件约 300 个，官方插件覆盖工具/技能/会话/沙箱/存储/调度/UI 等 120+

这条线的重点：Harness 从一个”概念热词”，变成了各家争相开源的基础设施层。LangChain 的 Harrison Chase 和黄仁勋公开对话时那句”未来的公司将建立在 Harness 之上”，现在 DeepSeek 用一个开源仓库给它做了注脚。

先说清楚 DSH 是什么、不是什么

很多人一看”DeepSeek 又发新东西”，第一反应是”新模型？”。不是。把这个搞清楚，后面才不会误解。

  • 不是 新的基础模型
  • 不是 又一个 API 客户端 / 套壳聊天框
  • 是 一套 Agent Harness——负责把模型接到文件系统、终端、网页、代码工具和其他 Agent 上，并组织上下文、工具调用和任务执行的运行框架

用我在 Harness Engineering 里的老比喻：模型是发动机，Harness 是整车。DeepSeek 以前只卖发动机，现在把整车的图纸也开源了。官方仓库在 github.com/deepseek-ai/deepseek-harness，当前版本 0.1.0-rc.5。

先从”用起来”说：用户眼里的 dsh 是什么

先抛开所有架构名词。你作为使用者拿到 dsh，体验是这样的：

装好之后（安装步骤后面讲），运行一行命令，浏览器弹出一个聊天界面，跟 ChatGPT 长得差不多。你在输入框里说”帮我把这个项目里的 console.log 全删掉”，它就真的去读文件、改代码、跑命令，一步步把活干完，而且每一步你都看得见。

这一层你根本不需要知道什么插件、什么 Cordis。对普通用户来说，dsh 就是”一个能动手干活、还能看着它每一步在干嘛的 AI 助手”，用起来跟 Hermes、Claude Code 没太大差别。

真正的不一样，从你想”改点什么”的那一刻才开始。

再往上一层：开发者想配置什么

用一阵子，你多半会冒出这几个念头：

  • 默认接的是 deepseek-v4-pro，我想换成本地模型，或者别家的模型
  • 我想给它加一个”查我司内部工单”的自定义工具
  • 每次改文件都弹审批太烦，我想关掉
  • 我不要浏览器界面，我想把它塞进 CI 脚本，跑完就退

换别的框架，这几件事有的能配、有的得改源码。在 dsh 里，这四件全是”改配置”就能搞定：换模型、加工具、关审批、去界面，一行源码都不用碰。

而你调好的这一整套设定，dsh 允许你存成一份带名字的配置，下次一行命令直接拉起来——这份东西官方叫 Profile。它自带两份现成的，正好对应两类最常见的用法：

Profile 你什么时候会用它
web 想在本地开个浏览器界面，跟 Agent 对话、盯着它干活
headless 不要界面、不起服务器，跑一次性任务就退，塞进 CI / 脚本 / 批量跑分

你也能自己攒一份，比如叫 mycompany：默认那套 + 你司内部工具 + 关掉沙箱，存好，团队里谁都能一行命令拉起同一套环境。

到这里为止，你干的所有事——换模型、加工具、开关能力——都只是在一份配置里选装/替换零件，没动过 dsh 一行源码。 那它凭什么能做到这点？

再往底层：凭什么什么都能配（一切皆插件 + Cordis）

答案就一条设计原则：

Everything is a Plugin（一切皆插件）。

模型、工具、技能、会话、沙箱、审批、存储、界面……甚至连 Agent 主循环本身，在 dsh 里全都是插件。你上面那些”换模型 / 加工具 / 关审批”，本质就是在插拔这些插件。既然什么都是插件，”配一下就换掉”自然就成立了。

这套插件能力，建立在一个叫 Cordis 的框架上。Cordis 你可以粗暴理解成 **”给程序用的 Docker Compose”**：每个功能是一个能独立启停的插件，Cordis 只负责按依赖关系把它们装起来、随时热插拔——它不懂”模型””工具”这些业务，只管装卸和依赖。

把这几层摆到一张图上，从下往上盖楼看：

   你的配置 Profile（web / headless / 自定义）   ← 一份清单，不是运行时的一层
   = 装哪些插件 / 换掉哪些 / 关掉哪些
                    │
                    │ dsh 照着它，把下面这棵插件树拼出来
                    ▼
============ dsh 运行时 = 一棵插件树 ============

  可选件    dsh-web-app（浏览器界面）/ dsh-headless（无界面·跑完即退）
  --------------------------------------------------
  开箱基线  dsh-base = 官方默认帮你装好的一批插件：
              模型 · 工具 · 持久化 · 沙箱 · 审批 · 凭据 · 遥测
              （每一样都是独立插件，都能换掉或关掉）
  --------------------------------------------------
  地基      Cordis：唯一拆不动，只管插件的装卸 + 依赖
================================================

图怎么读（从下往上）：

  • 最底 Cordis：唯一拆不动的地基，只管把插件装上/卸下。
  • 往上 dsh-base：官方默认帮你装好的一批插件，也就是你啥都不配时的”开箱状态”。
  • 再往上 可选件：要界面叠 web-app，要无头运行叠 headless。
  • 最顶上 你的配置 Profile：它不是运行时的一层，而是你那份”装哪些、换哪些、关哪些”的清单，dsh 照着它把下面这棵插件树拼出来。

回头看前面开发者那四个诉求，落到这张图上就一目了然了：换模型 = 换掉 dsh-base 里的模型插件；加工具 = 往里加个工具插件；关审批 = 关掉审批插件；去界面 = 不叠 web-app。全是在这棵树上插拔零件，没碰源码。

dsh-base 是写死的吗？——不是，它也是一堆插件

这点最容易误会：dsh-base 名字听着像”内核”，其实它只是官方帮你打包好的一批插件，里面模型、工具、沙箱、审批、凭据每一样都是独立插件。所以对它你能：

  • 覆盖：把默认沙箱换成你自己的实现
  • 关掉：不想要审批，禁用那个插件就行
  • 不用：极简 / 跑分场景，可以完全不装 dsh-base，直接在 Cordis 上搭一套最小组合

一句话：整套 dsh 里唯一拆不动的只有 Cordis，其余全是可换的插件；dsh-base 只是官方预设的那批，不是特权层。 这就是它敢讲”配置即架构”的底气——别人换个主循环、换个沙箱得改源码，dsh 里改配置就行。

顺便把两个官方术语点一下，后面会用到，也就不绕了：

  • Bundle：像 dsh-base、dsh-web-app 这种”打包好的一批插件”，官方就叫 Bundle。你可以理解成”一个功能套装”，装它就等于一次性把里面的插件都装上。
  • patch：在装好的插件树上做的局部微调（对应前面说的”覆盖 / 关掉”），比如”把默认沙箱换成我的””禁用审批”。

所以前面反复说的 Profile，说白了就是一句话：挑几个 Bundle 叠起来，再打几处 patch，存成一份带名字的配置。三个词的关系就是这么简单，不用记复杂了。

那”换东西”到底是换 Bundle 还是打 patch？

这是我自己一开始也绕不清的点：改一个东西，我是该换掉整个 dsh-base，还是在它上面改配置？答案是——两者都支持，而且它俩是同一套机制的不同力度。dsh 的插件树是”按层叠加、上层覆盖下层”，patch 只是这套叠加里最顶上的那一层。按改动力度从小到大，是一根连续的梯子：

力度 你干了啥 底层机制 典型场景
轻：打 patch 留着 dsh-base，只覆盖/关掉其中某个插件 在 base 之上盖一层覆盖 换模型、把默认沙箱换成自己的、关审批
中：换/加 Bundle 选择叠不叠某个套装，或叠上自己的套装 多叠一层 Bundle 去掉界面（不叠 web-app）、加一整套”内部工具”Bundle
重：完全自定义 干脆不叠 dsh-base，从 Cordis 起自己攒一批插件 只留地基、自己搭树 极简 / 跑分，或深度定制的产品

要澄清一个最容易误会的点：换”单个能力”（模型 / 沙箱 / 主循环），你不是换掉整个 dsh-base，而是用 patch 在它之上覆盖那一个插件，base 里其余的照旧。 所以根本不是二选一——真实用法几乎都是混着来：大部分插件用 dsh-base 的现成货，个别不满意的用 patch 覆盖，再额外叠一两个自己的 Bundle。

一句话记：能靠 patch 微调就别动 Bundle；要成套替换/新增才动 Bundle；想彻底自己说了算就不叠 base、从 Cordis 裸搭。 三档共用同一个”叠加 + 覆盖”引擎。

想再往下看一层的话，dsh 把这些能力按 ctx（共享上下文）上的键暴露出来，粒度大概是这样（不关心可跳过）：

包 职责 ctx 键
core/tools 工具注册表 + 带审批把关的执行 ctx.tools
core/session 仅追加的会话事件日志 ctx.sessions
core/agent-loop Agent 主循环的默认实现（可替换） ctx.agentLoop
llm/llm 消息与流式、模型适配器接缝 ctx.llm

连 agent-loop 都单独成包、还标着”可替换”，信号很明确：DSH 不想替你决定 Agent 该怎么循环，它只想给你一个能随便拆装的骨架。

四种运行模式

DSH 内置了四种模式，覆盖从日常干活到跑分的不同场景：

模式 工具组合 典型场景
标准 完整工具组合 日常开发、常规任务
PTC 由模型生成一段代码，用代码去组合多轮工具调用 复杂多步任务
极简 只保留一个 shell 工具 + 一个文件编辑工具 最小环境下的模型基准测试
创造 检查当前运行时、在内存里试验 Cordis 插件、据此组合出新模式 探索、自定义模式

PTC（让模型写代码来编排工具调用，而不是一轮一轮手动调）和”创造模式”（能在内存里现场捏插件、拼新模式）这两个，是我觉得最有意思的地方——它把”改 Harness”这件事从”改代码、重启”变成了”运行时热试验”。

快速上手

前置依赖：Node.js ≥ 20.12（推荐 22） —— 它内部用到了 util.parseEnv，这是 Node 20.12 才加的 API，用 过低版本 会直接在启动前报 parseEnv 的 SyntaxError。官方文档给的最快方式是一行 npx，但我实测这条路在 macOS 上会翻车（原因见下面的坑），更稳的是装进一个项目里再跑：

# 推荐：装进一个真实项目再跑（能把平台原生依赖装全）
mkdir dsh && cd dsh
npm init -y
npm install @deepseek-ai/dsh
npx dsh web
# 跑起来会打印： dsh web: http://127.0.0.1:3080

想读源码、做二次开发就走克隆构建：

# 想改源码/做插件开发选这个
git clone https://github.com/deepseek-ai/deepseek-harness.git
cd deepseek-harness
pnpm install
pnpm run build
pnpm dsh web

跑起来之后，浏览器打开就是一个 Web UI，可以接自己的模型开始用。仓库是个 Monorepo：apps/ 下是 cli 和 web 两个应用，packages/ 下是 core、llm、mcp、sandbox、context、plan、goal 等几十个包——光看目录结构就能感受到它开箱能力的广度。它已经支持 subagent（后台子代理）、MCP 和 Skill 这些扩展。

坑：直接 npx @deepseek-ai/dsh web 启动失败，报一长串 sharp 错误

我第一次就是照官方那行 npx 跑的，结果启动崩了，核心报错是这句（外面还套了好几层，最外层停在 dsh-app-boot/lib/index.js 的 throw 那行，很容易被误导成是它的问题）：

dsh: plugin tree failed to load: ...
  @deepseek-ai/dsh-attachment-local: Could not load the "sharp" module using the darwin-arm64 runtime
  • 现象：Node 版本明明够（≥20），但一启动就挂在 sharp 上。
  • 原因：dsh 的图片附件插件 dsh-attachment-local 依赖原生模块 sharp。npx 那种一次性安装有个老毛病——不会把平台专属的原生二进制装全：我去翻 npx 缓存，@img/ 下只有 sharp-libvips-darwin-arm64（libvips 库），缺了 @img/sharp-darwin-arm64（真正的 .node 绑定），于是加载即崩。这跟 Node 版本半毛钱关系没有。
  • 解决：别用 npx，改成上面”装进项目”的方式（npm install 会正确解析 optional 依赖，把 @img/sharp-darwin-arm64 装上），或者全局装 npm i -g @deepseek-ai/dsh 再 dsh web。装完 @img/ 下能看到 sharp-darwin-arm64，dsh web 就正常起来了。

一个自定义插件长什么样（下面是基于架构文档的示意写法，预览版 API 仍在迭代，具体签名以官方文档为准）：

// 一个最小的 dsh 插件：往工具注册表里加一个 "现在几点" 工具
// 插件本质就是一个拿到共享上下文 ctx 的函数，往上面挂能力
import type { Context } from '@deepseek-ai/dsh';

export const name = 'tool-now';

export function apply(ctx: Context) {
  // core/tools 通过 ctx.tools 暴露作用域化的工具注册表
  ctx.tools.register({
    name: 'now',
    description: '返回当前时间的 ISO 字符串',
    // 无参数工具，schema 给个空对象
    parameters: { type: 'object', properties: {} },
    async handler() {
      return new Date().toISOString();
    },
  });
}

这段代码的重点不在语法细节，而在那个心智模型：**你不是在”配置一个框架”，你是在”往一棵插件树上挂一根新枝”**。装卸、依赖、生命周期这些脏活，Cordis 帮你兜了。

和 Hermes、Claude Code 放一起比

之前写过 Hermes Agent 与 OpenClaw 工程化对比，正好把 DSH 拉进来对一下，选型时心里有数：

维度 DeepSeek Harness (DSH) Hermes Agent Claude Code
开发方 DeepSeek Nous Research Anthropic
协议 MIT MIT 闭源（商业）
主语言 TypeScript / Node Python TypeScript
核心抽象 一切皆插件 / Cordis 插件树 单体 Agent + Learning Loop 内置相对固定的 harness
模型绑定 不绑定（可接 40+ 模型） 不绑定 绑定 Claude
可替换粒度 连 Agent Loop 都是插件 配置 + Skills 层 有限
生态 预览两周约 300 社区插件 Skills / 社区插件 官方为主

我的看法：

  • 要极致的可组合、想连主循环都换掉——DSH 的抽象最彻底，Cordis 这套”配置即架构”给的自由度最大。代价是概念（Profile / Bundle / patch）有学习成本。
  • 要开箱即用、看重自进化 Learning Loop——Hermes 更省心，理念也更收敛。
  • 在 Anthropic 生态里、追求稳定体验——Claude Code 依然顺手，但你别指望能把它的 harness 拆开重装。

一句话：DSH 是”给工程师玩的乐高”，Hermes 是”配好的成品套装”，Claude Code 是”精装样板间”。 没有谁绝对更好，看你想要多少控制权。

战略意义：从卖模型到卖结果

这事不能只当技术新闻看。DeepSeek 亲自下场开源 Harness，背后是一次定位转变——从”模型提供商”往”全链路 AI 工作流解决方案构建者”走。

用 MIT 这种最宽松的协议、还刻意做”不绑定模型”（DSH 能接包括 DeepSeek 在内的 40 多种模型），我的解读是它想赌生态：把整车图纸开源出去、让全世界开发者往上挂插件，比自己闷头做一个封闭产品跑得快。内测两周 300 个插件的增速，某种程度上验证了这条路走得通。

对照 Harness 的新思考 那篇的判断——模型越来越强、越来越商品化，价值就越往”怎么驾驭模型干活”这一层迁移。DSH 正是把这层”驾驭力”产品化、开源化的一个动作。模型竞赛卷不动了，Harness 竞赛开始了。

我的判断

  1. DSH 不是新模型，是一套 Agent 运行框架，看它别用看模型的眼光
  2. “一切皆插件 + Cordis 元框架”是它的灵魂，连 Agent Loop 都能换，可组合性目前这一档里最强
  3. Profile / Bundle / dsh-base 分层是理解它的钥匙，本质是”配置即架构”
  4. 四种模式里，PTC 和创造模式最值得玩，把”改 Harness”变成了运行时热试验
  5. 选型上：要控制权选 DSH，要省心选 Hermes，要稳定体验用 Claude Code
  6. 它现在是 0.1.0-rc.5 开发者预览版，接口会变，尝鲜可以、别急着压生产
  7. 更大的信号是：竞争正从”模型竞赛”转向”Harness 竞赛”，基础设施层的仗才刚开打

小结

  1. DeepSeek 于 2026-08-13 开源 DeepSeek Harness（dsh）开发者预览版，MIT 协议，是一套把模型接到文件/终端/工具上的 Agent 运行框架
  2. 核心理念是”一切皆插件”，基于 Cordis 插件系统，连 Agent Loop 都是可替换插件
  3. 运行时是一棵按序叠加的插件树，用 Profile 组装、用 Bundle 分发，dsh-base 是每个 profile 的第一层
  4. 内置标准、PTC、极简、创造四种模式，分别对应日常开发、复杂编排、跑分和自定义探索
  5. npx @deepseek-ai/dsh web 一行起 Web UI，支持 subagent、MCP、Skill 扩展
  6. 相比 Hermes 和 Claude Code，DSH 的可组合粒度最细，代价是概念学习成本
  7. 更深层的意义：DeepSeek 从”卖模型”转向”卖结果”，行业竞争从模型竞赛进入 Harness 竞赛
