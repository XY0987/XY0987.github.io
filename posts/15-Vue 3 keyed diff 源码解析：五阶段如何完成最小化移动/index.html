Vue 3 keyed diff 源码解析：五阶段如何完成最小化移动

发表于2026|更新于2026|Vue框架及周边库
|字数总计:1.9k|阅读时长:7分钟

源码说明：本文分析的源码基于 vue@3.5.21，对应官方仓库为 vuejs/core，本文所在学习仓库为 XY0987/vue_ori_learning。

前言：前面已经分析过 render、patch 与组件更新。这一篇继续深入 children 更新中最经典、也最容易被问到的部分：Vue 3 的 keyed diff。它的核心不是“暴力比较所有节点”，而是先收缩确定区间，再只处理真正不确定的中间段。

keyed diff 从哪里进入

运行时更新 children 时会先进入 patchChildren。如果编译器标记了 KEYED_FRAGMENT，就直接走 patchKeyedChildren：

const patchChildren: PatchChildrenFn = (...) => {
  const { patchFlag, shapeFlag } = n2
  if (patchFlag > 0) {
    if (patchFlag & PatchFlags.KEYED_FRAGMENT) {
      patchKeyedChildren(c1 as VNode[], c2 as VNodeArrayChildren, ...)
      return
    }
  }
}

这里有一个关键点：KEYED_FRAGMENT 不是运行时猜出来的，而是编译器根据模板结构生成的。例如 v-for 带 :key 时，transformFor 会生成对应的 fragment flag。

五阶段总览

patchKeyedChildren 的流程可以概括为五步：

旧 children: a b c d e f g
新 children: a b e d c h f g

1. 从头同步：a b
2. 从尾同步：f g
3. 旧节点耗尽：挂载剩余新节点
4. 新节点耗尽：卸载剩余旧节点
5. 未知序列：只处理中间的 c d e / e d c h

源码入口：

// keyed diff 可以处理全 keyed，也可以处理 keyed / unkeyed 混合的 children。
// c1 是旧 children，c2 是新 children；整个算法先收缩确定区间，再只对中间未知区间做映射、patch 和最少移动。
// 五个阶段：前置同步 -> 后置同步 -> 纯新增 -> 纯删除 -> 未知序列 diff。
const patchKeyedChildren = (...) => {
  let i = 0
  const l2 = c2.length
  let e1 = c1.length - 1
  let e2 = l2 - 1
}

i 是头指针，e1 是旧 children 尾指针，e2 是新 children 尾指针。

阶段一：从头同步

while (i <= e1 && i <= e2) {
  const n1 = c1[i]
  const n2 = (c2[i] = optimized ? cloneIfMounted(c2[i] as VNode) : normalizeVNode(c2[i]))
  if (isSameVNodeType(n1, n2)) {
    patch(n1, n2, container, null, ...)
  } else {
    break
  }
  i++
}

只要新旧头部节点的 type 和 key 相同，就可以直接复用旧 DOM，并递归 patch 其内部差异。

这一阶段能快速处理最常见的追加场景：

旧: a b
新: a b c

a、b 被前置同步消费掉，后面只剩 c 要挂载。

阶段二：从尾同步

while (i <= e1 && i <= e2) {
  const n1 = c1[e1]
  const n2 = (c2[e2] = optimized ? cloneIfMounted(c2[e2] as VNode) : normalizeVNode(c2[e2]))
  if (isSameVNodeType(n1, n2)) {
    patch(n1, n2, container, null, ...)
  } else {
    break
  }
  e1--
  e2--
}

尾部同步能快速处理头部插入：

旧:     a b
新: c d a b

a、b 会从尾部被消费掉，剩下的 c d 直接挂载到正确位置。

阶段三：旧节点先耗尽，说明只需要新增

if (i > e1) {
  if (i <= e2) {
    const nextPos = e2 + 1
    const anchor = nextPos < l2 ? (c2[nextPos] as VNode).el : parentAnchor
    while (i <= e2) {
      patch(null, c2[i] = normalizeVNode(c2[i]), container, anchor, ...)
      i++
    }
  }
}

这里最值得注意的是 anchor。Vue 插入 DOM 不是简单 append，而是要插到“下一个已知新节点”之前：

旧: a b
新: c a b

前后同步后，只剩 c。它应该插到 a 之前，所以 anchor 是 a.el。

阶段四：新节点先耗尽，说明只需要删除

else if (i > e2) {
  while (i <= e1) {
    unmount(c1[i], parentComponent, parentSuspense, true)
    i++
  }
}

这一步处理删除场景：

旧: a b c
新: a b

同步完 a b 后，旧的 c 不再存在，直接卸载。

阶段五：未知序列 diff

当前后都无法继续同步时，说明中间区间发生了复杂变更：

旧: a b [c d e] f g
新: a b [e d c h] f g

此时 Vue 会做三件事：

  1. 为新 children 建立 key -> newIndex 映射。
  2. 遍历旧 children，找到可复用节点并 patch，不存在的卸载。
  3. 根据最长递增子序列，倒序执行新增和移动。

5.1 建立 key 映射

const keyToNewIndexMap: Map<PropertyKey, number> = new Map()
for (i = s2; i <= e2; i++) {
  const nextChild = (c2[i] = optimized ? cloneIfMounted(c2[i] as VNode) : normalizeVNode(c2[i]))
  if (nextChild.key != null) {
    keyToNewIndexMap.set(nextChild.key, i)
  }
}

这样遍历旧节点时，可以通过 key 快速知道它在新列表中的位置。

5.2 记录新旧索引关系

const toBePatched = e2 - s2 + 1
let moved = false
let maxNewIndexSoFar = 0
const newIndexToOldIndexMap = new Array(toBePatched)
for (i = 0; i < toBePatched; i++) newIndexToOldIndexMap[i] = 0

newIndexToOldIndexMap 是理解 Vue 3 diff 的关键。

它的含义是：

newIndexToOldIndexMap[newIndex - s2] = oldIndex + 1

为什么要 +1？因为 0 被保留为特殊值，表示“这个新节点没有对应的旧节点，需要新挂载”。

举个例子：

旧: c d e
新: e d c h

遍历旧节点后，可能得到：
newIndexToOldIndexMap = [5, 4, 3, 0]

含义：

新区间节点 新位置 对应旧位置 + 1 说明
e 0 5 旧索引 4
d 1 4 旧索引 3
c 2 3 旧索引 2
h 3 0 新增节点

5.3 为什么需要最长递增子序列

遍历旧节点时，Vue 会用 maxNewIndexSoFar 判断新索引是否保持递增：

newIndexToOldIndexMap[newIndex - s2] = i + 1
if (newIndex >= maxNewIndexSoFar) {
  maxNewIndexSoFar = newIndex
} else {
  moved = true
}

如果新索引一直递增，说明节点相对顺序没变，不需要移动。否则就计算最长递增子序列：

const increasingNewIndexSequence = moved
  ? getSequence(newIndexToOldIndexMap)
  : EMPTY_ARR
j = increasingNewIndexSequence.length - 1

最长递增子序列代表“可以留在原地的一组节点”。其他节点才需要移动。

为什么倒序移动

最后阶段倒序遍历新 children：

for (i = toBePatched - 1; i >= 0; i--) {
  const nextIndex = s2 + i
  const nextChild = c2[nextIndex] as VNode
  const anchorVNode = c2[nextIndex + 1] as VNode
  const anchor = nextIndex + 1 < l2 ? anchorVNode.el || anchorVNode.placeholder : parentAnchor
  if (newIndexToOldIndexMap[i] === 0) {
    patch(null, nextChild, container, anchor, ...)
  } else if (moved) {
    if (j < 0 || i !== increasingNewIndexSequence[j]) {
      move(nextChild, container, anchor, MoveType.REORDER)
    } else {
      j--
    }
  }
}

倒序的好处是：右侧节点已经处理过，可以直接作为当前节点的 anchor。

例如新列表是：

[e, d, c, h]

从右往左处理时：

  • 先处理 h，如果是新增，就插到 f 之前。
  • 再处理 c，它应该插到 h 之前。
  • 再处理 d，插到 c 之前。

这样每次都能找到稳定的“下一个节点”。

keyed diff 的设计取舍

汇总diff：Vue 3 的 keyed diff 会先用头头比较、尾尾比较尽量收缩确定区域；如果剩下中间未知区域，就通过 key 建立新旧节点的映射，找出哪些节点可以复用、哪些需要新增或删除；最后用最长递增子序列找出“相对顺序已经正确、不需要移动”的节点，其他节点再按需要移动或挂载。

Vue 3 的 keyed diff 并不是追求理论上的编辑距离最优，而是针对 UI 更新做了工程取舍：

设计 目的
头尾同步 快速跳过常见的追加、删除、头尾插入
key 映射 避免在未知区间中重复查找 keyed 节点
newIndexToOldIndexMap 同时记录复用关系、新增节点和 LIS 输入
LIS 尽量减少真实 DOM 移动
倒序移动 利用右侧已处理节点作为 anchor

小结

理解 patchKeyedChildren，重点抓住三句话：

  1. 先用头尾同步缩小问题规模。
  2. 未知区间先 patch / unmount，再统一 mount / move。
  3. 最长递增子序列表示“可以不动的节点”，从而减少真实 DOM 移动。

这也是 Vue 3 runtime 的一个典型设计：编译期通过 patchFlag 尽量让运行时少做判断，运行时再用高性价比算法完成真实 DOM 更新。
