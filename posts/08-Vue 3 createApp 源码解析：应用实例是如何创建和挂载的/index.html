Vue 3 createApp 源码解析：应用实例是如何创建和挂载的

发表于2026|更新于2026|Vue框架及周边库
|字数总计:3.3k|阅读时长:14分钟

源码说明：本文分析的源码基于 vue@3.5.21，对应官方仓库为 vuejs/core，本文所在学习仓库为 XY0987/vue_ori_learning。

前言：响应式系统看完后，可以进入运行时主线。createApp(App).mount('#app') 是大多数 Vue 应用的起点。这篇先看应用实例如何创建、平台差异如何注入，以及根组件最终如何变成根 VNode 交给渲染器。

先给结论

createApp(App).mount('#app') 的核心链路是：

runtime-dom createApp
  │
  ├─ ensureRenderer()
  │    └─ createRenderer(rendererOptions)
  │
  ├─ runtime-core createApp
  │    └─ createAppAPI(render, hydrate)
  │
  ├─ 返回 app 实例
  │
  └─ 重写 app.mount
       ├─ selector 转 DOM container
       ├─ 处理容器内模板
       ├─ 清空容器
       └─ 调 runtime-core mount
            ├─ 创建根 VNode
            ├─ 绑定 appContext
            └─ render(vnode, container)

这里有一个重要分层：

包 职责
runtime-dom 注入 DOM 操作能力，处理 selector、容器、DOM 挂载细节
runtime-core 创建 app 实例，维护 app context，创建根 VNode，调用平台无关 render
renderer 根据 VNode 进入 patch 流程，真正挂载组件和 DOM

createApp 不是直接创建 DOM，而是创建一个应用实例；真正接管 DOM 的动作发生在 mount 之后。

runtime-dom：给 runtime-core 注入浏览器能力

runtime-core 本身是平台无关的，它不知道 DOM 怎么创建、属性怎么更新。浏览器平台能力由 runtime-dom 注入：

// runtime-dom 给 runtime-core 注入浏览器平台能力：
// nodeOps 负责增删查改 DOM 节点，patchProp 负责更新 class/style/event/attribute 等属性。
const rendererOptions = /*@__PURE__*/ extend({ patchProp }, nodeOps)

nodeOps 负责 DOM 节点操作，比如创建元素、插入、删除。patchProp 负责属性更新，比如 class、style、事件和普通 attribute。

这组 rendererOptions 会传给 createRenderer：

function ensureRenderer() {
  // 首次真正需要渲染时才创建 renderer，避免只使用响应式 API 时把渲染器逻辑也打进包里。
  return (
    renderer ||
    (renderer = createRenderer<Node, Element | ShadowRoot>(rendererOptions))
  )
}

这里是懒创建。只有真正调用渲染相关 API 时，才创建 renderer。这样如果用户只从 Vue 里使用响应式 API，渲染器逻辑仍有机会被 tree-shaking 掉。

SSR hydration 也有单独的懒创建入口：

function ensureHydrationRenderer() {
  // SSR hydration 使用带 hydrate 能力的 renderer，同样保持按需创建。
  renderer = enabledHydration
    ? renderer
    : createHydrationRenderer(rendererOptions)
  enabledHydration = true
  return renderer as HydrationRenderer
}

createRenderer：生成平台渲染器

createRenderer 在 runtime-core/src/renderer.ts 中。它接收平台操作能力，返回 render 和 createApp。

export function createRenderer<
  HostNode = RendererNode,
  HostElement = RendererElement,
>(options: RendererOptions<HostNode, HostElement>): Renderer<HostElement> {
  return baseCreateRenderer<HostNode, HostElement>(options)
}

这就是 Vue 运行时可跨平台的关键：

  • 浏览器平台传入 DOM 操作。
  • 自定义渲染器可以传入自己的 host 操作。
  • 核心 patch、组件、调度逻辑复用同一套 runtime-core。

runtime-dom 的 createApp 包装

浏览器端导出的 createApp 不是直接来自 runtime-core，而是包了一层 DOM 逻辑：

// 浏览器端 createApp 是对 runtime-core createApp 的一层 DOM 平台包装。
// 打包后，createApp 传递的参数通常是根组件对象或 SFC 编译产物。
export const createApp = ((...args) => {
  const app = ensureRenderer().createApp(...args)

  if (__DEV__) {
    injectNativeTagCheck(app)
    injectCompilerOptionsCheck(app)
  }

  const { mount } = app
  app.mount = (containerOrSelector: Element | ShadowRoot | string): any => {
    // runtime-dom 额外支持 selector 字符串；runtime-core 只关心具体 host container。
    const container = normalizeContainer(containerOrSelector)
    if (!container) return

    const component = app._component
    if (!isFunction(component) && !component.render && !component.template) {
      // 如果根组件没有 render/template，则把挂载容器的 innerHTML 作为模板。
      // 这只适用于 full build；runtime-only 构建会在开发环境提示编译器配置无效。
      // __UNSAFE__
      // Reason: potential execution of JS expressions in in-DOM template.
      // The user must make sure the in-DOM template is trusted. If it's
      // rendered by the server, the template should not contain any user data.
      component.template = container.innerHTML
      // 2.x compat check
      if (__COMPAT__ && __DEV__ && container.nodeType === 1) {
        for (let i = 0; i < (container as Element).attributes.length; i++) {
          const attr = (container as Element).attributes[i]
          if (attr.name !== 'v-cloak' && /^(?:v-|:|@)/.test(attr.name)) {
            compatUtils.warnDeprecation(
              DeprecationTypes.GLOBAL_MOUNT_CONTAINER,
              null,
            )
            break
          }
        }
      }
    }

    // 挂载前清空容器内容，Vue 后续会通过 renderer 接管这个容器。
    if (container.nodeType === 1) {
      container.textContent = ''
    }
    // 调用 runtime-core 的 mount，最终会创建根 VNode 并交给 render/patch 流程。
    const proxy = mount(container, false, resolveRootNamespace(container))
    if (container instanceof Element) {
      container.removeAttribute('v-cloak')
      container.setAttribute('data-v-app', '')
    }
    return proxy
  }

  return app
}) as CreateAppFunction<Element>

这一层主要做四件事：

  1. 创建浏览器 renderer。
  2. 调用 runtime-core 的 createApp 得到 app。
  3. 重写 app.mount，让它支持 selector 字符串和 DOM 容器处理。
  4. 调用原始 mount，进入平台无关挂载流程。

这解释了为什么你可以写：

createApp(App).mount('#app')

因为 '#app' 到 DOM 元素的转换发生在 runtime-dom，不是 runtime-core。

SSR createSSRApp 的区别

createSSRApp 走 hydration renderer：

export const createSSRApp = ((...args) => {
  const app = ensureHydrationRenderer().createApp(...args)

  if (__DEV__) {
    injectNativeTagCheck(app)
    injectCompilerOptionsCheck(app)
  }

  const { mount } = app
  app.mount = (containerOrSelector: Element | ShadowRoot | string): any => {
    // SSR 场景不会清空容器，而是把已有服务端 DOM 交给 hydrate 对齐并激活事件。
    const container = normalizeContainer(containerOrSelector)
    if (container) {
      return mount(container, true, resolveRootNamespace(container))
    }
  }

  return app
}) as CreateAppFunction<Element>

和普通 createApp 最大的区别是：

  • 普通客户端挂载会清空容器，然后重新渲染。
  • SSR hydration 不清空容器，而是复用服务端已经生成的 DOM，进行对齐和事件激活。

AppContext：每个应用独立的上下文

runtime-core 里，createAppContext 会创建一个应用级上下文：

export function createAppContext(): AppContext {
  // AppContext 是一个应用级容器：全局配置、全局组件/指令、provide、缓存都挂在这里。
  // 每次 createApp 都会创建独立 context，因此不同 app 之间的全局注册不会互相污染。
  return {
    app: null as any,
    config: {
      isNativeTag: NO,
      performance: false,
      globalProperties: {},
      optionMergeStrategies: {},
      errorHandler: undefined,
      warnHandler: undefined,
      compilerOptions: {},
    },
    mixins: [],
    components: {},
    directives: {},
    provides: Object.create(null),
    optionsCache: new WeakMap(),
    propsCache: new WeakMap(),
    emitsCache: new WeakMap(),
  }
}

这个 context 很重要。你通过 app 注册的内容基本都在这里：

API 存放位置
app.config context.config
app.component context.components
app.directive context.directives
app.mixin context.mixins
app.provide context.provides

这就是为什么多个 Vue 应用可以挂在同一个页面上，并且全局组件、插件、provide 不互相污染：每个 app 都有自己的 AppContext。

所以这套 app API 是平台无关的。

app 实例上有哪些核心能力

createApp 返回的 app 对象包含很多方法。

插件安装

      use(plugin: Plugin, ...options: any[]) {
        // 插件以 app 为粒度去重，同一个插件不能重复安装到同一个 app。
        if (installedPlugins.has(plugin)) {
          __DEV__ && warn(`Plugin has already been applied to target app.`)
        } else if (plugin && isFunction(plugin.install)) {
          installedPlugins.add(plugin)
          plugin.install(app, ...options)
        } else if (isFunction(plugin)) {
          installedPlugins.add(plugin)
          plugin(app, ...options)
        } else if (__DEV__) {
          warn(
            `A plugin must either be a function or an object with an "install" ` +
              `function.`,
          )
        }
        return app
      },

插件可以是函数，也可以是带 install 方法的对象。Vue 会用 WeakSet 按 app 粒度去重。

全局 mixin、组件和指令

      mixin(mixin: ComponentOptions) {
        if (__FEATURE_OPTIONS_API__) {
          // 全局 mixin 存在 app context 中，只影响当前 app 下的组件选项合并。
          if (!context.mixins.includes(mixin)) {
            context.mixins.push(mixin)
          } else if (__DEV__) {
            warn(
              'Mixin has already been applied to target app' +
                (mixin.name ? `: ${mixin.name}` : ''),
            )
          }
        } else if (__DEV__) {
          warn('Mixins are only available in builds supporting Options API')
        }
        return app
      },

      component(name: string, component?: Component): any {
        if (__DEV__) {
          validateComponentName(name, context.config)
        }
        if (!component) {
          return context.components[name]
        }
        if (__DEV__ && context.components[name]) {
          warn(`Component "${name}" has already been registered in target app.`)
        }
        // 全局组件注册到当前 app context，后续组件解析时会从这里查找。
        context.components[name] = component
        return app
      },

      directive(name: string, directive?: Directive) {
        if (__DEV__) {
          validateDirectiveName(name)
        }

        if (!directive) {
          return context.directives[name] as any
        }
        if (__DEV__ && context.directives[name]) {
          warn(`Directive "${name}" has already been registered in target app.`)
        }
        // 全局指令同样注册到当前 app context。
        context.directives[name] = directive
        return app
      },

这些全局能力都挂在 context 上，因此只对当前 app 生效。

app.provide

      provide(key, value) {
        if (__DEV__ && (key as string | symbol) in context.provides) {
          if (hasOwn(context.provides, key as string | symbol)) {
            warn(
              `App already provides property with key "${String(key)}". ` +
                `It will be overwritten with the new value.`,
            )
          } else {
            // #13212, context.provides can inherit the provides object from parent on custom elements
            warn(
              `App already provides property with key "${String(key)}" inherited from its parent element. ` +
                `It will be overwritten with the new value.`,
            )
          }
        }

        // app.provide 写入应用级 provides，所有根组件下的后代都能通过 inject 读取。
        context.provides[key as string | symbol] = value

        return app
      },

app.provide 是应用级 provide，根组件下的后代都可以通过 inject 读取。

mount：根组件如何进入渲染流程

mount 是 createApp 最关键的部分。

      // createApp(App).mount(container) 最终会进入这里。
      // runtime-dom 在外层负责把 selector 转为 DOM，这里只处理平台无关的 host container。
      mount(
        rootContainer: HostElement,
        isHydrate?: boolean,
        namespace?: boolean | ElementNamespace,
      ): any {
        if (!isMounted) {
          // #5571
          if (__DEV__ && (rootContainer as any).__vue_app__) {
            warn(
              `There is already an app instance mounted on the host container.\n` +
                ` If you want to mount another app on the same host container,` +
                ` you need to unmount the previous app by calling \`app.unmount()\` first.`,
            )
          }
          // 根组件挂载前先创建根 VNode，后续 renderer 会从这个 VNode 开始 patch。
          const vnode = app._ceVNode || createVNode(rootComponent, rootProps)
          // 把 appContext 挂到根 VNode，组件实例创建时会继承它，用于全局组件/指令/provide 等解析。
          vnode.appContext = context

          if (namespace === true) {
            namespace = 'svg'
          } else if (namespace === false) {
            namespace = undefined
          }

          // HMR root reload
          if (__DEV__) {
            context.reload = () => {
              const cloned = cloneVNode(vnode)
              // HMR 重载根组件时复用 VNode 信息，但清空 el，避免走 hydration 复用旧 DOM。
              cloned.el = null
              // casting to ElementNamespace because TS doesn't guarantee type narrowing
              // over function boundaries
              render(cloned, rootContainer, namespace as ElementNamespace)
            }
          }

          if (isHydrate && hydrate) {
            hydrate(vnode as VNode<Node, Element>, rootContainer as any)
          } else {
            // 首次挂载走 render(vnode, container)，内部会进入 renderer 的 patch 流程。
            render(vnode, rootContainer, namespace)
          }
          isMounted = true
          app._container = rootContainer
          // 在容器上保存 app 引用，供重复挂载检查、devtools 和 telemetry 使用。
          ;(rootContainer as any).__vue_app__ = app

          if (__DEV__ || __FEATURE_PROD_DEVTOOLS__) {
            app._instance = vnode.component
            devtoolsInitApp(app, version)
          }

          return getComponentPublicInstance(vnode.component!)

这段逻辑可以拆成几步：

  1. 检查当前 app 是否已经挂载。
  2. 检查容器上是否已有其他 app。
  3. 基于根组件创建根 VNode。
  4. 把 appContext 绑定到根 VNode。
  5. 根据是否 hydration，调用 hydrate 或 render。
  6. 记录挂载状态和容器。
  7. 返回根组件公开实例。

这里最关键的是：

const vnode = app._ceVNode || createVNode(rootComponent, rootProps)
vnode.appContext = context
render(vnode, rootContainer, namespace)

也就是说，mount 并不是直接挂组件，而是先把根组件转成根 VNode，再交给 renderer。

unmount：卸载入口

卸载时，Vue 会执行插件清理函数，然后调用 render(null, container)：

      onUnmount(cleanupFn: () => void) {
        if (__DEV__ && typeof cleanupFn !== 'function') {
          warn(
            `Expected function as first argument to app.onUnmount(), ` +
              `but got ${typeof cleanupFn}`,
          )
        }
        // 插件可以通过 app.onUnmount 注册应用卸载时的清理函数。
        pluginCleanupFns.push(cleanupFn)
      },

      unmount() {
        if (isMounted) {
          callWithAsyncErrorHandling(
            pluginCleanupFns,
            app._instance,
            ErrorCodes.APP_UNMOUNT_CLEANUP,
          )
          // render(null, container) 是卸载入口，renderer 会卸载整棵 VNode 树。
          render(null, app._container)
          if (__DEV__ || __FEATURE_PROD_DEVTOOLS__) {
            app._instance = null
            devtoolsUnmountApp(app)
          }
          delete app._container.__vue_app__
        } else if (__DEV__) {
          warn(`Cannot unmount an app that is not mounted.`)
        }
      },

render(null, container) 是一个很典型的设计：

  • render(vnode, container) 表示挂载或更新。
  • render(null, container) 表示卸载。

runWithContext：没有组件实例时如何 inject

runWithContext 会临时设置当前 app：

      runWithContext(fn) {
        // 临时把当前 app 设置为 active app，让没有组件实例的代码也能使用 inject。
        const lastApp = currentApp
        currentApp = app
        try {
          return fn()
        } finally {
          currentApp = lastApp
        }
      },

它解决的是这类场景：没有当前组件实例，但仍希望在某段函数里通过 inject 读取 app 级 provide。

一个完整流程

以最常见的代码为例：

createApp(App).mount('#app')

内部流程是：

createApp(App)
  │
  ▼
runtime-dom createApp
  │
  ├─ ensureRenderer()
  │    └─ createRenderer(rendererOptions)
  │
  └─ renderer.createApp(App)
       │
       ▼
     runtime-core createApp
       │
       ├─ 创建 AppContext
       ├─ 创建 app 对象
       └─ 返回 app

app.mount('#app')
  │
  ▼
runtime-dom mount 包装
  │
  ├─ normalizeContainer('#app')
  ├─ 清空容器
  └─ 调 runtime-core mount(container)
       │
       ├─ createVNode(rootComponent, rootProps)
       ├─ vnode.appContext = context
       ├─ render(vnode, container)
       └─ 返回根组件公开实例

这条链路串起来后，下一步就自然进入 renderer.ts：render(vnode, container) 内部是如何走到 patch，以及根组件是如何被挂载的。

小结

  1. runtime-dom 负责注入浏览器 DOM 能力，并包装 createApp 的 DOM 相关行为。
  2. runtime-core 通过 createAppAPI(render, hydrate) 创建平台无关的 app API。
  3. 每个 app 都有独立的 AppContext，全局组件、指令、插件、provide 都是 app 级隔离的。
  4. mount 会把根组件转成根 VNode，并把 appContext 挂到 VNode 上。
  5. 真正的挂载入口是 render(vnode, container)，后续会进入 renderer 的 patch 流程。
  6. 卸载入口是 render(null, container)。
