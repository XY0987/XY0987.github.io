Vue 3 编译时优化源码解析：PatchFlags、Block Tree 与静态提升

发表于2026|更新于2026|Vue框架及周边库
|字数总计:1.7k|阅读时长:7分钟

源码说明：本文分析的源码基于 vue@3.5.21，对应官方仓库为 vuejs/core，本文所在学习仓库为 XY0987/vue_ori_learning。

前言：前面已经看过模板如何变成 render 函数，也看过 renderer 如何 patch VNode。这一篇专门补上 Vue 3 编译时优化这条线：编译器不只是生成代码，还会生成运行时更新需要的提示，让 renderer 少做无效 diff。

先给结论

Vue 3 编译时优化可以概括成一句话：

编译器提前分析模板结构，把“哪里会变、哪里不会变”写进 render 代码，运行时根据这些提示跳过不必要的比较。

主要优化有几类：

优化 解决的问题
PatchFlags 告诉运行时当前 VNode 哪些部分是动态的
dynamicProps 精确告诉运行时哪些 prop key 需要比较
Block Tree 把动态子节点收集成数组，更新时只 patch 动态节点
静态提升 静态 VNode / props 提到 render 外，避免重复创建
事件缓存 缓存稳定事件函数，避免每次 render 生成新函数

PatchFlags：编译器给运行时的更新提示

PatchFlags 的注释说得很直接：

/**
 * Patch flags are optimization hints generated by the compiler.
 * when a block with dynamicChildren is encountered during diff, the algorithm
 * enters "optimized mode". In this mode, we know that the vdom is produced by
 * a render function generated by the compiler, so the algorithm only needs to
 * handle updates explicitly marked by these patch flags.
 *
 * Patch flags can be combined using the | bitwise operator and can be checked
 * using the & operator, e.g.
 *
 * ```js
 * const flag = TEXT | CLASS
 * if (flag & TEXT) { ... }
 * ```
 */

常见标记有：

export enum PatchFlags {
  TEXT = 1,
  CLASS = 1 << 1,
  STYLE = 1 << 2,
  PROPS = 1 << 3,
  FULL_PROPS = 1 << 4,
}

比如模板：

<div :id="id">{{ msg }}</div>

会生成类似：

createElementBlock('div', { id: _ctx.id }, toDisplayString(_ctx.msg), 9)

这里的 9 可以理解成：

TEXT(1) | PROPS(8) = 9

它告诉运行时：这个节点的动态点主要是文本和部分 props。运行时就不用完整比较所有东西。

transformElement：动态标记在哪里生成

元素转换时会先准备几个变量：

let vnodeProps: VNodeCall['props']
let vnodeChildren: VNodeCall['children']
let patchFlag: VNodeCall['patchFlag'] | 0 = 0
let vnodeDynamicProps: VNodeCall['dynamicProps']
let dynamicPropNames: string[] | undefined
let vnodeDirectives: VNodeCall['directives']

let shouldUseBlock = false

vnodeProps = propsBuildResult.props
patchFlag = propsBuildResult.patchFlag
dynamicPropNames = propsBuildResult.dynamicPropNames

如果子节点是动态文本，会加 TEXT：

const hasDynamicTextChild =
  type === NodeTypes.INTERPOLATION ||
  type === NodeTypes.COMPOUND_EXPRESSION
if (
  hasDynamicTextChild &&
  getConstantType(child, context) === ConstantTypes.NOT_CONSTANT
) {
  patchFlag |= PatchFlags.TEXT
}

如果属性里有动态 class、style、props，会在 buildProps 里分析：

// patchFlag analysis
if (hasDynamicKeys) {
  patchFlag |= PatchFlags.FULL_PROPS
} else {
  if (hasClassBinding && !isComponent) {
    patchFlag |= PatchFlags.CLASS
  }
  if (hasStyleBinding && !isComponent) {
    patchFlag |= PatchFlags.STYLE
  }
  if (dynamicPropNames.length) {
    patchFlag |= PatchFlags.PROPS
  }
  if (hasHydrationEventBinding) {
    patchFlag |= PatchFlags.NEED_HYDRATION
  }
}

最后把这些信息塞进 createVNodeCall：

node.codegenNode = createVNodeCall(
  context,
  vnodeTag,
  vnodeProps,
  vnodeChildren,
  patchFlag === 0 ? undefined : patchFlag,
  vnodeDynamicProps,
  vnodeDirectives,
  !!shouldUseBlock,

所以 patchFlag 不是 codegen 阶段临时猜的，而是在 transform 阶段基于 AST 分析出来的。

dynamicProps：只比较可能变化的 prop

如果动态 prop 名称是静态可知的，编译器会记录到 dynamicPropNames：

} else if (name !== 'key' && !dynamicPropNames.includes(name)) {
  dynamicPropNames.push(name)
}

// treat the dynamic class and style binding of the component as dynamic props
if (
  isComponent &&
  (name === 'class' || name === 'style') &&
  !dynamicPropNames.includes(name)
) {
  dynamicPropNames.push(name)
}

比如：

<div :id="id" :title="title" />

编译器知道动态 key 是：

['id', 'title']

运行时更新 props 时，就可以只比较这些 key，而不是全量比较所有属性。

Block Tree：只收集动态子节点

patchFlag 解决的是“单个 VNode 哪些地方会变”，Block Tree 解决的是“这棵子树里哪些节点需要更新”。

源码注释里说：

// can divide a template into nested blocks, and within each block the node
// structure would be stable. This allows us to skip most children diffing
// and only worry about the dynamic nodes (indicated by patch flags).
export const blockStack: VNode['dynamicChildren'][] = []

openBlock 会开启一个动态节点收集容器：

export function openBlock(disableTracking = false): void {
  blockStack.push((currentBlock = disableTracking ? null : []))
}

export function closeBlock(): void {
  blockStack.pop()
  currentBlock = blockStack[blockStack.length - 1] || null
}

createElementBlock 会把当前 block 的动态子节点保存到 block vnode 上：

function setupBlock(vnode: VNode) {
  // save current block children on the block vnode
  vnode.dynamicChildren =
    isBlockTreeEnabled > 0 ? currentBlock || (EMPTY_ARR as any) : null
  // close block
  closeBlock()
  // a block is always going to be patched, so track it as a child of its
  // parent block
  if (isBlockTreeEnabled > 0 && currentBlock) {
    currentBlock.push(vnode)
  }
  return vnode
}

简单理解：

普通 VNode 树：按层级递归 diff
Block Tree：提前收集动态节点，更新时直接 patch dynamicChildren

这就是为什么编译器会生成：

openBlock(), createElementBlock(...)

它不是多余代码，而是为了让运行时知道哪些节点是动态的。

静态提升：不变的东西不要重复创建

完全静态的节点和 props，可以提升到 render 函数外面。

cacheStatic 会识别可缓存的静态节点：

const constantType = doNotHoistNode
  ? ConstantTypes.NOT_CONSTANT
  : getConstantType(child, context)
if (constantType > ConstantTypes.NOT_CONSTANT) {
  if (constantType >= ConstantTypes.CAN_CACHE) {
    ;(child.codegenNode as VNodeCall).patchFlag = PatchFlags.CACHED
    toCache.push(child)
    continue
  }

对于静态 props / dynamicProps，也可以 hoist：

if (codegenNode.type === NodeTypes.VNODE_CALL) {
  const props = getNodeProps(child)
  if (props) {
    codegenNode.props = context.hoist(props)
  }
  if (codegenNode.dynamicProps) {
    codegenNode.dynamicProps = context.hoist(codegenNode.dynamicProps)
  }
}

比如：

<div class="card"><span>hello</span></div>

如果它完全静态，就没必要每次 render 都重新创建同样的 VNode 和 props 对象。静态提升就是把它们放到 render 外复用。

事件缓存：稳定函数不要每次重建

cacheHandlers 用来缓存稳定事件处理函数。配置说明在 compiler options 里：

/**
 * Cache v-on handlers to avoid creating new inline functions on each render,
 * also avoids the need for dynamically patching the handlers by wrapping it.
 *
 * e.g `@click="foo"` by default is compiled to `{ onClick: foo }`. With this
 * option it's compiled to:
 * ```js
 * { onClick: _cache[0] || (_cache[0] = e => _ctx.foo(e)) }
 * ```
 */
cacheHandlers?: boolean

比如事件处理函数每次 render 都新建，会让运行时以为 props 变了。缓存后，同一个 handler 可以复用，减少不必要的事件 patch。

运行时如何消费这些优化信息

编译器生成提示后，运行时会在 patchElement 里消费它们。你在 renderer 文章里已经见过这条线：

patchFlag > 0
  -> 根据 TEXT / CLASS / STYLE / PROPS 等标记走快速路径

dynamicChildren
  -> 走 patchBlockChildren，只更新动态子节点

所以这套优化不是编译器自嗨，而是编译器和运行时之间的协议：

编译器：我提前告诉你哪里会变
运行时：我只更新你标出来的地方

小结

  1. PatchFlags 是编译器生成的动态更新提示。
  2. dynamicProps 记录可精确比较的动态 prop key。
  3. Block Tree 会把动态子节点收集到 dynamicChildren，避免整棵树递归 diff。
  4. 静态提升把不变的 VNode / props 提到 render 外复用。
  5. 事件缓存避免每次 render 创建新函数导致无意义更新。
  6. Vue 3 的性能优化核心不是某个单点技巧，而是编译器和运行时共同遵守的一套更新协议。
