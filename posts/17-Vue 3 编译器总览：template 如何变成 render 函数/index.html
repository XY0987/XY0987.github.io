Vue 3 编译器总览：template 如何变成 render 函数

发表于2026|更新于2026|Vue框架及周边库
|字数总计:1.2k|阅读时长:4分钟

源码说明：本文分析的源码基于 vue@3.5.21，对应官方仓库为 vuejs/core，本文所在学习仓库为 XY0987/vue_ori_learning。

前言：运行时主线看完后，再看编译器就更容易理解了。编译器的目标不是直接操作 DOM，而是把模板字符串变成 render 函数；运行时再执行 render，得到 VNode，最后交给 renderer patch。

先给结论

Vue 3 模板编译主线是三段式：

template string
  │
  ▼
parse
  │  生成模板 AST
  ▼
transform
  │  转换 AST，生成 codegenNode，收集 helpers/components/directives
  ▼
codegen
     输出 render 函数字符串

入口在 baseCompile：

  const resolvedOptions = extend({}, options, {
    prefixIdentifiers,
  })
  // 1. parse：模板字符串先解析成 AST；如果传入的已经是 RootNode，则直接复用。
  const ast = isString(source) ? baseParse(source, resolvedOptions) : source
  // 2. 准备 transform 预设：节点转换 + 指令转换。
  const [nodeTransforms, directiveTransforms] =
    getBaseTransformPreset(prefixIdentifiers)

  if (!__BROWSER__ && options.isTS) {
    const { expressionPlugins } = options
    if (!expressionPlugins || !expressionPlugins.includes('typescript')) {
      options.expressionPlugins = [...(expressionPlugins || []), 'typescript']
    }
  }

  // 3. transform：遍历 AST，处理 v-if/v-for/v-bind 等语法，并为后续 codegen 准备 codegenNode。
  transform(
    ast,
    extend({}, resolvedOptions, {
      nodeTransforms: [
        ...nodeTransforms,
        ...(options.nodeTransforms || []), // user transforms
      ],
      directiveTransforms: extend(
        {},
        directiveTransforms,
        options.directiveTransforms || {}, // user transforms
      ),
    }),
  )

  // 4. codegen：把转换后的 AST 生成 render 函数字符串。
  return generate(ast, resolvedOptions)

transform 预设是什么

getBaseTransformPreset 定义了 compiler-core 默认的转换管线：

export function getBaseTransformPreset(
  prefixIdentifiers?: boolean,
): TransformPreset {
  // 编译器核心转换预设：第一项是节点转换管线，第二项是指令转换表。
  // 顺序很重要，例如 v-if/v-for 这类结构化指令需要先改写 AST，再交给 element/text 转换生成 codegenNode。
  return [
    [
      transformOnce,
      transformIf,
      transformMemo,
      transformFor,
      ...(__COMPAT__ ? [transformFilter] : []),
      ...(!__BROWSER__ && prefixIdentifiers
        ? [
            // order is important
            trackVForSlotScopes,
            transformExpression,
          ]
        : __BROWSER__ && __DEV__
          ? [transformExpression]
          : []),
      transformSlotOutlet,
      transformElement,
      trackSlotScopes,
      transformText,
    ],
    {
      on: transformOn,
      bind: transformBind,
      model: transformModel,
    },
  ]
}

这里可以看到两类转换：

类型 例子 作用
NodeTransform transformIf、transformFor、transformElement、transformText 处理节点结构
DirectiveTransform transformOn、transformBind、transformModel 处理具体指令属性

编译器和运行时如何衔接

模板：

<div :id="id">{{ msg }}</div>

编译后大致会生成类似：

function render(_ctx, _cache) {
  return openBlock(), createElementBlock('div', { id: _ctx.id }, toDisplayString(_ctx.msg), 9)
}

这段 render 执行后会返回 VNode。运行时 renderer 再对这个 VNode 执行 patch。

所以完整链路是：

template
  │
  ▼
render function
  │
  ▼
VNode
  │
  ▼
patch
  │
  ▼
DOM

编译时优化：不只是生成 render 函数

编译器不只是把 template 翻译成 render 函数，它还会顺手把“哪些地方会变、哪些地方不会变”标出来，让运行时少做判断。

可以先看刚才这个生成结果：

function render(_ctx, _cache) {
  return openBlock(), createElementBlock('div', { id: _ctx.id }, toDisplayString(_ctx.msg), 9)
}

最后这个 9 就是 patchFlag。它不是随便写的数字，而是编译器告诉运行时：这个节点有哪些动态内容。比如动态文本、动态 props、动态 class、动态 style 等。

PatchFlags 的定义在 shared 包里：

export enum PatchFlags {
  /**
   * Indicates an element with dynamic textContent (children fast path)
   */
  TEXT = 1,

  /**
   * Indicates an element with dynamic class binding.
   */
  CLASS = 1 << 1,

  /**
   * Indicates an element with dynamic style
   */
  STYLE = 1 << 2,

  /**
   * Indicates an element that has non-class/style dynamic props.
   */
  PROPS = 1 << 3,

  /**
   * Indicates an element with props with dynamic keys.
   */
  FULL_PROPS = 1 << 4,
}

所以运行时 patch 时，不用每次都完整比较所有属性和子节点，而是优先看这些标记：

编译时优化 大概作用
patchFlag 动态标记 告诉运行时哪些内容可能变化，比如文本、class、style、props
dynamicProps 精确记录哪些 prop key 是动态的，运行时只比这些 key
openBlock / createElementBlock 收集动态子节点，形成 block tree，更新时只 patch 动态节点
静态提升 hoistStatic 把完全静态的 VNode / props 提到 render 外面，避免每次 render 都重新创建
事件缓存 cacheHandlers 缓存稳定事件函数，避免每次 render 创建新函数导致无意义更新

我的理解是，Vue 3 编译器的核心价值就在这里：它不是只做“语法翻译”，而是在编译期提前分析模板结构，把优化信息塞进生成代码里。运行时 renderer 拿到这些信息后，就可以跳过大量不必要的 diff。

简单说：

编译器：提前告诉运行时哪里会变
运行时：根据这些提示只更新真正可能变化的地方

小结

  1. baseCompile 是 compiler-core 的主入口。
  2. 编译分为 parse、transform、codegen 三阶段。
  3. parse 把模板字符串变成 AST。
  4. transform 处理指令、表达式、元素、文本，并生成 codegenNode。
  5. codegen 把 AST/codegenNode 输出成 render 函数字符串。
  6. 编译器还会生成 patchFlag、block tree、静态提升等优化信息，让运行时少做 diff。
  7. render 函数执行后产生 VNode，最终交给运行时 renderer。
