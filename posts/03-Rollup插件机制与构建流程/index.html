Rollup 插件机制与构建流程

发表于2026|更新于2026|工程化
|字数总计:1.7k|阅读时长:6分钟

前言：为什么单独写一篇 Rollup 插件机制？因为 Vite 的插件 API 就是 Rollup 插件 API 的超集，Rolldown 也兼容 Rollup 插件。也就是说，搞懂 Rollup 的钩子模型，你就同时理解了 Vite 插件、Rolldown 插件怎么写。这是整个现代构建生态里复用率最高的一块知识。

Rollup 的构建流程分两个阶段

Rollup 把一次构建清晰地切成两个阶段，理解这个划分是理解插件的前提。

┌─────────────── Build 阶段 ───────────────┐
│  从入口出发，构建模块依赖图              │
│  resolveId → load → transform           │
│  （解析路径 → 读取内容 → 转换内容）       │
└──────────────────┬───────────────────────┘
                   ▼
┌─────────────── Output 阶段 ──────────────┐
│  根据依赖图生成最终产物                  │
│  renderChunk → generateBundle → writeBundle │
│  （渲染代码块 → 生成产物 → 写入磁盘）      │
└──────────────────────────────────────────┘
  • Build 阶段：关注「输入」，把源码读进来、转换、建立模块之间的依赖关系图。
  • Output 阶段：关注「输出」，决定怎么分块、生成什么格式、写到哪里。

一个关键认知：Build 阶段只做一次，Output 阶段可以做多次。因为你可能要从同一份依赖图同时输出 ESM 和 CJS 两种格式，那 Build 跑一次，Output 跑两次。

插件就是一组钩子函数

Rollup 插件本质上是一个对象，里面挂着一些「钩子」（hook）。Rollup 在构建流程的特定时机调用这些钩子，插件借此介入。

最常用的几个钩子，按执行顺序：

钩子 阶段 作用
resolveId Build 决定一个 import 解析成什么路径
load Build 根据路径返回模块内容
transform Build 转换模块内容（最常用）
buildEnd Build 依赖图构建完成
renderChunk Output 对每个 chunk 的代码做最后处理
generateBundle Output 拿到完整产物，可增删文件
writeBundle Output 产物已写盘

resolveId / load / transform 三件套

这三个钩子配合，能实现「凭空造一个虚拟模块」。举个经典例子：让 import data from 'virtual:my-data' 这种根本不存在的路径能用。

// rollup-plugin-virtual-data.js
export default function virtualData() {
  const virtualId = 'virtual:my-data'
  // Rollup 约定：虚拟模块 id 加 \0 前缀，避免被其他插件误处理
  const resolvedId = '\0' + virtualId

  return {
    name: 'virtual-data',

    // 1. 解析：遇到 virtual:my-data，告诉 Rollup 它的真实 id
    resolveId(source) {
      if (source === virtualId) return resolvedId
      return null // 返回 null 表示"我不管，交给下一个插件"
    },

    // 2. 加载：根据 id 提供内容（因为文件并不真实存在）
    load(id) {
      if (id === resolvedId) {
        return `export default ${JSON.stringify({ version: '1.0.0' })}`
      }
      return null
    },
  }
}

用起来：

// src/main.js
import data from 'virtual:my-data'
console.log(data.version) // 1.0.0

这个模式在 Vite 生态里极其常见，很多「自动生成路由」「注入环境信息」的插件都是这么干的。

transform 钩子则是改造已有文件内容，比如把自定义语法转掉：

export default function replaceVersion() {
  return {
    name: 'replace-version',
    transform(code, id) {
      // 只处理 .js 文件，把 __VERSION__ 替换成真实版本号
      if (!id.endsWith('.js')) return null
      if (!code.includes('__VERSION__')) return null
      return {
        code: code.replace(/__VERSION__/g, '"1.0.0"'),
        map: null, // 简单替换可不生成 sourcemap，复杂转换应返回 map
      }
    },
  }
}

钩子返回 null 是个重要约定：表示「这个插件不处理，交给后面的插件或 Rollup 默认逻辑」。不要随便返回非 null 值打断链路。

钩子的执行顺序与控制

多个插件的同名钩子会按一定顺序执行。Rollup 提供了控制手段：

export default function myPlugin() {
  return {
    name: 'my-plugin',
    transform: {
      order: 'pre', // 'pre' 提前 | 'post' 延后 | 默认按插件顺序
      handler(code, id) {
        return null
      },
    },
  }
}

钩子还分几种执行类型，理解它们能避免踩坑：

类型 含义 例子
async/sync 是否异步 大多数钩子支持 async
first 多个插件中，第一个返回非 null 的生效 resolveId、load
sequential 按顺序串行，前一个结果传给后一个 transform
parallel 可并行 buildStart

resolveId 是 first 类型——一旦某个插件返回了结果，后面的就不再处理了。这就是为什么插件顺序很重要，也是为什么不处理时一定要返回 null。

Rollup、Vite、Rolldown 插件的关系

这是这篇最值钱的一句话：Vite 插件 = Rollup 插件 + Vite 独有钩子。

Rollup 插件钩子（resolveId / load / transform / ...）
        ↑ 完全复用
Vite 插件（额外加 config / configureServer / transformIndexHtml 等）
        ↑ 兼容
Rolldown（Rust 重写，但兼容 Rollup 插件 API）

一个 Vite 插件长这样：

// vite-plugin-demo.js
export default function demo() {
  return {
    name: 'vite-plugin-demo',

    // —— 下面这些是 Rollup 也有的通用钩子 ——
    resolveId(id) { /* ... */ return null },
    transform(code, id) { /* ... */ return null },

    // —— 下面这些是 Vite 独有的钩子 ——
    config(config) {
      // 修改 Vite 配置
    },
    configureServer(server) {
      // 介入 dev server，加中间件等
    },
    transformIndexHtml(html) {
      // 改 index.html
      return html.replace('<title></title>', '<title>Demo</title>')
    },
  }
}

所以学习路径很清晰：先学 Rollup 通用钩子（resolveId/load/transform 等），这部分到处都能用；再学 Vite 独有钩子，处理 dev server、HTML 这些 Rollup 管不到的事。

实战提醒：Vite 独有钩子在 vite build 时部分不生效（因为没有 dev server），写插件时要注意区分 apply: 'serve' 还是 'build'。

export default function onlyDev() {
  return {
    name: 'only-dev',
    apply: 'serve', // 只在 dev 时启用；'build' 则只在构建时
    configureServer() { /* ... */ },
  }
}

一个完整可跑的 Rollup 配置

mkdir rollup-demo && cd rollup-demo
npm init -y
npm i -D rollup

// rollup.config.mjs
import virtualData from './rollup-plugin-virtual-data.js'

export default {
  input: 'src/main.js',
  output: [
    { file: 'dist/index.mjs', format: 'es' },   // Output 阶段跑一次
    { file: 'dist/index.cjs', format: 'cjs' },  // 再跑一次
  ],
  plugins: [virtualData()],
}

// src/main.js
import data from 'virtual:my-data'
export const version = data.version

npx rollup -c
# 看 dist/ 下同时生成了 .mjs 和 .cjs，且虚拟模块被正确注入

这个例子同时展示了两点：插件如何造虚拟模块（Build 阶段），以及一份依赖图如何输出多种格式（Output 阶段跑多次）。

小结

  1. Rollup 构建分 Build 和 Output 两阶段：Build 建依赖图（只跑一次），Output 生成产物（可跑多次输出多格式）。
  2. 插件是挂在流程钩子上的对象，最常用的是 resolveId、load、transform 三件套。
  3. resolveId + load 能造虚拟模块，transform 改造已有文件内容，不处理时务必返回 null。
  4. 钩子有 first/sequential 等执行类型，插件顺序会影响结果。
  5. Vite 插件是 Rollup 插件的超集，Rolldown 也兼容 Rollup 插件，所以 Rollup 钩子是复用率最高的知识。
  6. 区分 dev 和 build：Vite 独有钩子用 apply: 'serve' | 'build' 控制生效时机。
