手写并发控制：从 Promise.all 到自定义 Spawn

发表于2026|更新于2026|前端基础
|字数总计:1.7k|阅读时长:6分钟

面试时经常被问到：「手写一个支持并发的 spawn 函数」。这个问题本质上是在考察你对异步任务调度的理解——不是简单地把一堆 Promise 扔给 Promise.all 就完事了，而是要精确控制同时执行的任务数量。

从一个真实场景说起

假设你要批量上传 100 张图片，如果用 Promise.all 一口气全部并发：

// ❌ 100 个请求同时发出，浏览器/服务器可能扛不住
const urls = Array.from({ length: 100 }, (_, i) => `/api/upload/${i}`);
await Promise.all(urls.map(url => fetch(url)));

服务端直接给你返回 429 Too Many Requests，浏览器也可能因为连接数过多卡死。

我们需要的是一个并发池（Pool）：最多允许 N 个任务同时执行，某个任务完成后自动补充下一个。

核心设计思路

先理清几个关键点：

概念 说明
任务队列 所有待执行的异步函数
并发上限 同时运行的最大任务数
活跃任务 当前正在执行的任务集合
调度策略 任务完成后从队列取下一个补充

核心流程：

┌─────────────────────────────────────────────┐
│              并发池工作流程                    │
├─────────────────────────────────────────────┤
│                                             │
│   [任务队列] ──→ [并发槽位(最大N个)]          │
│      │              │                       │
│      │         ┌────┴────┐                  │
│      │         │         │                  │
│      ▼         ▼         ▼                  │
│   等待中    执行中     执行中                 │
│             (完成)    (进行中)               │
│                │                            │
│                ▼                            │
│          取下一个任务                         │
│                                             │
└─────────────────────────────────────────────┘

基础版实现

最直观的思路：维护一个计数器 + 队列。

/**
 * 并发控制函数 - 基础版
 * @param {number} concurrency - 最大并发数
 * @param {Function[]} tasks - 异步任务数组，每个任务返回 Promise
 * @returns {Promise<any[]>} 所有任务的执行结果
 */
async function spawn(concurrency, tasks) {
  const results = [];
  const executing = new Set(); // 正在执行的任务集合

  for (const task of tasks) {
    // 创建任务 Promise 并立即启动
    const promise = task().then(result => {
      results.push(result);
      executing.delete(promise); // 完成后从集合移除
      return result;
    });

    executing.add(promise);

    // 如果达到并发上限，等待任意一个完成
    if (executing.size >= concurrency) {
      await Promise.race(executing);
    }
  }

  // 等待所有剩余任务完成
  await Promise.all(executing);
  return results;
}

测试一下：

// 模拟异步任务
function createTask(name, delay) {
  return () =>
    new Promise(resolve => {
      setTimeout(() => {
        console.log(`${name} 完成`);
        resolve(name);
      }, delay);
    });
}

// 创建10个任务，延迟各不相同
const tasks = [
  createTask('A', 300),
  createTask('B', 200),
  createTask('C', 100),
  createTask('D', 400),
  createTask('E', 150),
];

// 最大并发数为2
spawn(2, tasks).then(console.log);
// 输出顺序示例（取决于具体调度）:
// C 完成 (100ms)
// E 完成 (150ms)
// B 完成 (200ms)
// A 完成 (300ms)
// D 完成 (400ms)
// 最终结果: ['A', 'B', 'C', 'D', 'E']

结果顺序问题

上面的基础版有个问题：结果顺序不保证和输入一致。因为 results.push 取决于哪个任务先完成。

如果需要保持顺序：

async function spawnOrdered(concurrency, tasks) {
  const results = new Array(tasks.length);
  const executing = new Set();

  for (let i = 0; i < tasks.length; i++) {
    const index = i; // 闭包捕获当前索引
    const promise = tasks[index]().then(result => {
      results[index] = result; // 按索引写入，保证顺序
      executing.delete(promise);
      return result;
    });

    executing.add(promise);

    if (executing.size >= concurrency) {
      await Promise.race(executing);
    }
  }

  await Promise.all(executing);
  return results;
}

关键改动：用 results[index] 替代 results.push()，按原始位置存放结果。

进阶版：完整的并发池

实际项目中我们往往需要更多能力：错误处理、进度回调、动态添加任务等。

class ConcurrentPool {
  /**
   * @param {Object} options
   * @param {number} options.concurrency - 最大并发数
   * @param {Function} [options.onProgress] - 进度回调 (completed, total)
   * @param {Function} [options.onError] - 错误处理回调
   */
  constructor({ concurrency, onProgress, onError } = {}) {
    this.concurrency = concurrency;
    this.onProgress = onProgress;
    this.onError = onError;
    this.tasks = [];        // 待执行队列
    this.executing = new Set(); // 正在执行的任务
    this.completed = 0;     // 已完成任务数
    this.results = [];      // 结果收集
  }

  /** 添加任务到队列 */
  add(task) {
    this.tasks.push(task);
    return this;
  }

  /** 执行所有任务 */
  async run() {
    while (this.tasks.length > 0 || this.executing.size > 0) {
      // 填充并发槽位
      while (
        this.executing.size < this.concurrency &&
        this.tasks.length > 0
      ) {
        const task = this.tasks.shift();
        this._executeTask(task);
      }

      // 等待至少一个任务完成
      if (this.executing.size > 0) {
        await Promise.race(this.executing);
      }
    }
    return this.results;
  }

  _executeTask(task) {
    const promise = task()
      .then(result => {
        this.results.push(result);
        this.completed++;
        this.onProgress?.(this.completed, this.results.length + this.tasks.length + this.executing.size);
      })
      .catch(error => {
        this.completed++;
        this.onError?.(error, task);
        this.onProgress?.(this.completed, this.results.length + this.tasks.length + this.executing.size);
      })
      .finally(() => {
        this.executing.delete(promise);
      });

    this.executing.add(promise);
  }
}

使用示例：

const pool = new ConcurrentPool({
  concurrency: 3,
  onProgress: (done, total) =>
    console.log(`进度: ${done}/${total}`),
  onError: (err, task) =>
    console.error(`任务失败:`, err.message),
});

for (let i = 0; i < 10; i++) {
  pool.add(() =>
    fetch(`/api/resource/${i}`).then(r => r.json())
  );
}

const results = await pool.run();
console.log('全部完成:', results);

几种方案对比

方案 优点 缺点 适用场景
Promise.all 简单直接 无并发限制 少量请求（< 5个）
p-all 库 成熟稳定 引入外部依赖 生产环境
基础版 spawn 无依赖、轻量 功能有限 面试、简单场景
ConcurrentPool 类 功能完整、可扩展 代码量稍多 复杂业务

我的实战建议：如果是面试，手写基础版就够展示理解了；如果是项目里真要用，优先考虑成熟的库如 p-limit 或 p-all，别自己造轮子。

踩坑记录

坑1：Promise.race 的陷阱

Promise.race 返回的是第一个 settle（resolve 或 reject）的 Promise 的值。如果任务可能 reject，需要确保错误被正确捕获，否则未捕获的异常会导致整个 pool 崩溃。

// ❌ 危险：reject 会中断 race
const promise = task().catch(err => {
  // 必须处理错误，不能让它裸 reject
  return null; // 或者用一个特殊标记表示失败
});

// ✅ 安全：每个任务内部处理自己的错误
const promise = task()
  .then(result => ({ status: 'fulfilled', value: result }))
  .catch(error => ({ status: 'rejected', error }));

坑2：内存泄漏风险

如果任务创建后长时间不 resolve（比如网络请求挂起），executing 集合会越来越大。生产环境建议加上超时机制：

function withTimeout(promise, ms) {
  return Promise.race([
    promise,
    new Promise((_, reject) =>
      setTimeout(() => reject(new Error('超时')), ms)
    ),
  ]);
}

小结

  1. 并发池的核心思想：维护一个固定大小的执行槽位集合，用 Promise.race 监控完成状态，及时补充新任务
  2. 顺序保证：用索引写入而非 push，可以保证结果顺序与输入一致
  3. 错误隔离：每个任务内部自行 catch，避免单个任务失败导致整体崩溃
  4. 超时保护：生产环境务必加超时机制，防止任务挂起占用资源
  5. 选型建议：面试写基础版，项目用成熟库（p-limit、p-all）
