Vue 3 computed 源码解析：缓存、脏值与惰性求值

发表于2026|更新于2026|Vue框架及周边库
|字数总计:2.5k|阅读时长:10分钟

源码说明：本文分析的源码基于 vue@3.5.21，对应官方仓库为 vuejs/core，本文所在学习仓库为 XY0987/vue_ori_learning。

前言：computed 对外和 ref 很像，都通过 .value 读取值。但 computed 不是普通容器，它的核心是“派生状态”：值由 getter 计算得来，并且具备缓存、脏值标记和惰性求值能力。

先给结论

computed 的核心机制可以概括为：

能力 实现方式
像 ref 一样被读取 ComputedRefImpl 实现 .value
缓存计算结果 _value 保存上次计算结果
依赖变化后不立刻重算 notify 只标记 DIRTY
下次读取时按需重算 get value 中调用 refreshComputed
自己依赖别的响应式数据 ComputedRefImpl 本身也是 Subscriber
别人依赖它的值 computed.dep 维护订阅者

一句话：

computed 是一个“既订阅别人，又被别人订阅”的特殊 ref。

computed 和 ref 的区别

ref 的值是主动写进去的：

const count = ref(1)
count.value = 2

computed 的值是通过 getter 推导出来的：

const count = ref(1)
const double = computed(() => count.value * 2)

二者都通过 .value 读取，但含义不同：

对比项 ref computed
值从哪里来 外部直接赋值 getter 计算得来
是否缓存 普通保存值 缓存 getter 结果
依赖变化时 直接触发依赖 先标记脏值，等下次读取再计算
是否可写 默认可写 函数形式只读，对象形式可写

computed 入口：函数形式和对象形式

computed 支持两种用法。

只读 computed：

const double = computed(() => count.value * 2)

可写 computed：

const plusOne = computed({
  get: () => count.value + 1,
  set: val => {
    count.value = val - 1
  },
})

源码入口会根据参数类型拆出 getter 和 setter：

export function computed<T>(
  getterOrOptions: ComputedGetter<T> | WritableComputedOptions<T>,
  debugOptions?: DebuggerOptions,
  isSSR = false,
) {
  let getter: ComputedGetter<T>
  let setter: ComputedSetter<T> | undefined

  // 函数形式是只读 computed；对象形式通过 get/set 创建可写 computed。
  if (isFunction(getterOrOptions)) {
    getter = getterOrOptions
  } else {
    getter = getterOrOptions.get
    setter = getterOrOptions.set
  }

  const cRef = new ComputedRefImpl(getter, setter, isSSR)

  if (__DEV__ && debugOptions && !isSSR) {
    cRef.onTrack = debugOptions.onTrack
    cRef.onTrigger = debugOptions.onTrigger
  }

  return cRef as any
}

所以 computed 的运行时核心就是创建 ComputedRefImpl。

ComputedRefImpl 的两个身份

ComputedRefImpl 有两个身份。

第一，它是 ref，对外暴露 .value：

export interface ComputedRef<T = any> extends BaseComputedRef<T> {
  // computed 对外也表现为 ref，但只读 computed 只能读取 value。
  readonly value: T
}

export interface WritableComputedRef<T, S = T> extends BaseComputedRef<T, S> {
  [WritableComputedRefSymbol]: true
}

第二，它是 Subscriber，可以订阅其他响应式数据：

export class ComputedRefImpl<T = any> implements Subscriber {
  /**
   * computed 缓存的当前值。只有首次读取或依赖变脏后重新读取，才会更新它。
   * @internal
   */
  _value: any = undefined
  /**
   * 依赖当前 computed.value 的订阅者会记录在这个 dep 上。
   * 注意：computed 自身依赖了哪些响应式数据，记录在 deps/depsTail 上。
   * @internal
   */
  readonly dep: Dep = new Dep(this)
  /**
   * computed 本身也是一种 ref。
   * @internal
   */
  readonly __v_isRef = true
  // TODO isolatedDeclarations ReactiveFlags.IS_REF
  /**
   * 没有 setter 的 computed 是只读的。
   * @internal
   */
  readonly __v_isReadonly: boolean
  // TODO isolatedDeclarations ReactiveFlags.IS_READONLY
  // A computed is also a subscriber that tracks other deps
  /**
   * computed getter 运行时读取到的依赖链表头部。
   * @internal
   */
  deps?: Link = undefined
  /**
   * computed getter 运行时读取到的依赖链表尾部。
   * @internal
   */
  depsTail?: Link = undefined
  /**
   * 默认 DIRTY，表示第一次读取时需要执行 getter 求值。
   * @internal
   */
  flags: EffectFlags = EffectFlags.DIRTY
  /**
   * 记录上次刷新时的全局版本号，用于没有任何响应式变化时快速复用缓存。
   * @internal
   */
  globalVersion: number = globalVersion - 1
  /**
   * SSR 下 computed 没有渲染 effect 订阅，缓存策略会略有不同。
   * @internal
   */
  isSSR: boolean
  /**
   * 批处理队列中的下一个订阅者。
   * @internal
   */
  next?: Subscriber = undefined

这里要分清两组依赖：

computed 依赖别人：
  computed.deps / computed.depsTail

别人依赖 computed：
  computed.dep

举个例子：

const count = ref(1)
const double = computed(() => count.value * 2)

effect(() => {
  console.log(double.value)
})

依赖关系可以理解成：

count.dep ──► double 这个 computed

double.dep ──► 外层 effect

也就是说，computed 站在中间：上游依赖响应式数据，下游被 effect 或其他 computed 依赖。

get value：先收集外部依赖，再刷新自己

读取 computed.value 时，会进入这里：

  get value(): T {
    // 先收集“谁依赖这个 computed.value”。
    const link = __DEV__
      ? this.dep.track({
          target: this,
          type: TrackOpTypes.GET,
          key: 'value',
        })
      : this.dep.track()
    // 再按需刷新 computed 自身缓存。缓存仍有效时，这一步会快速返回。
    refreshComputed(this)
    // computed 重新求值后，同步外层订阅 link 的版本号，避免后续误判为脏。
    if (link) {
      link.version = this.dep.version
    }
    return this._value
  }

这里的顺序很关键：

  1. 先 this.dep.track()：收集谁依赖了这个 computed。
  2. 再 refreshComputed(this)：判断自己是否需要重新计算。
  3. 返回缓存值 _value。

为什么先收集外部依赖？因为外层 effect 读取的是 double.value，它关心的是 computed 这个派生值。如果 computed 以后变了，外层 effect 应该重新执行。

notify：依赖变化时只标记脏值

当 computed 依赖的响应式数据变化时，computed 会被通知。

  /**
   * @internal
   */
  notify(): true | void {
    // computed 依赖的数据变化时，不会立刻重新计算，只是标记为脏值。
    this.flags |= EffectFlags.DIRTY
    if (
      !(this.flags & EffectFlags.NOTIFIED) &&
      // avoid infinite self recursion
      activeSub !== this
    ) {
      // 进入 computed 批处理队列，并返回 true 让 Dep.notify 继续通知 computed 自己的 dep。
      batch(this, true)
      return true
    } else if (__DEV__) {
      // TODO warn
    }
  }

注意这里没有执行 getter（你传给的computed(() => …) 的那个函数）。它只是：

  1. 标记 DIRTY。
  2. 把 computed 放进 computed 批处理队列。
  3. 返回 true，让上层 Dep.notify 继续通知 computed.dep。

这就是 computed 的惰性：依赖变化时不立刻重算，等下一次读取 .value 时才重算。

refreshComputed：缓存与脏值判断的核心

真正决定要不要重新计算的是 refreshComputed，它在 effect.ts 里。

export function refreshComputed(computed: ComputedRefImpl): undefined {
  // 已经被追踪且不是脏值，说明缓存仍然可用。
  if (
    computed.flags & EffectFlags.TRACKING &&
    !(computed.flags & EffectFlags.DIRTY)
  ) {
    return
  }
  computed.flags &= ~EffectFlags.DIRTY

  // 全局版本快速路径：如果自上次刷新以来没有任何响应式变更，直接复用缓存值。
  if (computed.globalVersion === globalVersion) {
    return
  }
  computed.globalVersion = globalVersion

  // 非 SSR 场景下，如果 computed 已经求值过，且自身依赖没有变脏，也可以直接复用缓存。
  if (
    !computed.isSSR &&
    computed.flags & EffectFlags.EVALUATED &&
    ((!computed.deps && !(computed as any)._dirty) || !isDirty(computed))
  ) {
    return
  }
  computed.flags |= EffectFlags.RUNNING

  const dep = computed.dep
  const prevSub = activeSub
  const prevShouldTrack = shouldTrack
  // computed 自身也是 Subscriber，执行 getter 时需要作为 activeSub 收集它依赖的响应式数据。
  activeSub = computed
  shouldTrack = true

  try {
    prepareDeps(computed)
    const value = computed.fn(computed._value)
    if (dep.version === 0 || hasChanged(value, computed._value)) {
      computed.flags |= EffectFlags.EVALUATED
      computed._value = value
      dep.version++
    }
  } catch (err) {
    dep.version++
    throw err
  } finally {
    activeSub = prevSub
    shouldTrack = prevShouldTrack
    cleanupDeps(computed)
    computed.flags &= ~EffectFlags.RUNNING
  }
}

这段代码有三层“能不算就不算”的判断。

第一层：已经追踪且不是脏值，直接返回。

computed.flags & EffectFlags.TRACKING && !(computed.flags & EffectFlags.DIRTY)

第二层：全局响应式版本没变，直接返回。

computed.globalVersion === globalVersion

第三层：computed 已经求值过，并且自己的依赖没有变脏，直接返回。

computed.flags & EffectFlags.EVALUATED && !isDirty(computed)

只有这些快速路径都不满足时，才会真正执行：

const value = computed.fn(computed._value)

这就是 computed 缓存的核心。

computed 如何收集自己的依赖

refreshComputed 在执行 getter 前会设置：

  const dep = computed.dep
  const prevSub = activeSub
  const prevShouldTrack = shouldTrack
  // computed 自身也是 Subscriber，执行 getter 时需要作为 activeSub 收集它依赖的响应式数据。
  activeSub = computed
  shouldTrack = true

  try {
    prepareDeps(computed)
    const value = computed.fn(computed._value)

这和 ReactiveEffect.run 很像。区别是这里的 activeSub 不是普通 effect，而是 computed 自己。

所以执行 getter 时：

const double = computed(() => count.value * 2)

读取 count.value 会把 double 这个 computed 收集到 count.dep 中。

count.dep ──► double computed

当 count.value 变化后，double 会收到通知，进入 notify，标记为 DIRTY。

为什么 computed 是惰性的

考虑这段代码：

const count = ref(1)
const double = computed(() => {
  console.log('computed run')
  return count.value * 2
})

count.value++
count.value++
count.value++

console.log(double.value)

如果 computed 不是惰性的，每次 count.value++ 都会重新执行 getter。

但 Vue 的 computed 是惰性的：count 变化时只标记 DIRTY，直到最后读取 double.value，才重新计算一次。

这个过程是：

count.value++
  │
  ▼
通知 double computed
  │
  ▼
double.flags |= DIRTY
  │
  ▼
不执行 getter

读取 double.value
  │
  ▼
refreshComputed(double)
  │
  ▼
执行 getter，更新缓存

这也是 computed 性能好的原因：它避免了无用计算。

可写 computed 的 set

只读 computed 没有 setter，写入会在开发环境警告。

  set value(newValue) {
    if (this.setter) {
      // 可写 computed 的赋值会转交给用户传入的 setter。
      this.setter(newValue)
    } else if (__DEV__) {
      warn('Write operation failed: computed value is readonly')
    }
  }

可写 computed 的赋值只是转交给用户提供的 setter，它自己不直接修改 _value。

const count = ref(1)

const plusOne = computed({
  get: () => count.value + 1,
  set: val => {
    count.value = val - 1
  },
})

plusOne.value = 10
console.log(count.value) // 9

这个设计让 computed 保持“派生状态”的定位：真正的源数据还是外部响应式状态，computed 只是负责读和写的映射关系。

一个完整流程

以这个例子为例：

const count = ref(1)
const double = computed(() => count.value * 2)

effect(() => {
  console.log(double.value)
})

count.value++

第一次执行：

effect 执行
  │
  ▼
读取 double.value
  │
  ├─ double.dep.track() 收集外层 effect
  │
  └─ refreshComputed(double)
       │
       ├─ activeSub = double
       ├─ 执行 getter
       └─ 读取 count.value，把 double 收集到 count.dep

修改 count.value：

count.dep.trigger()
  │
  ▼
double.notify()
  │
  ├─ 标记 DIRTY
  └─ 通知 double.dep
       │
       ▼
     外层 effect 重新执行
       │
       ▼
     再次读取 double.value
       │
       ▼
     refreshComputed 重新计算

这条链路说明 computed 既是订阅者，也是依赖源。

小结

  1. computed 对外是 ref，通过 .value 读取派生值。
  2. ComputedRefImpl 同时是 Subscriber，所以它可以订阅其他响应式数据。
  3. computed.dep 记录“谁依赖 computed.value”，computed.deps 记录“computed 依赖谁”。
  4. 依赖变化时，computed 不立刻执行 getter，只标记 DIRTY。
  5. 下一次读取 .value 时，refreshComputed 根据脏值和版本号决定是否重新计算。
  6. 可写 computed 的 setter 只是转发写入，真正修改的通常仍是源响应式数据。
