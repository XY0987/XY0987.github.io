Vue 3 内置组件源码解析：KeepAlive、Teleport 与 Suspense 如何接入渲染器

发表于2026|更新于2026|Vue框架及周边库
|字数总计:1.5k|阅读时长:6分钟

源码说明：本文分析的源码基于 vue@3.5.21，对应官方仓库为 vuejs/core，本文所在学习仓库为 XY0987/vue_ori_learning。

前言：前面看了组件、renderer、scheduler 和 keyed diff。这一篇补一块运行时高级能力：Vue 的内置组件。KeepAlive、Teleport、Suspense 看起来像组件，但它们并不是普通组件，它们都需要和 renderer 深度协作。

先给结论

这三个内置组件分别解决不同问题：

内置组件 核心能力 和 renderer 的关系
Teleport 把子节点渲染到另一个 DOM 容器 自己实现 process / move / remove，直接使用 renderer internals
KeepAlive 缓存组件实例，切换时不销毁 通过 activate / deactivate 控制组件移动和缓存
Suspense 等待异步依赖，期间显示 fallback 自己维护 suspense boundary，控制主内容和 fallback 的挂载时机

它们的共同点是：

对外像组件，对内是 renderer 的特殊分支。

Teleport：渲染位置和组件层级解耦

Teleport 的识别方式很直接：

Teleport 会从 renderer internals 里拿到平台操作：

首次挂载时，它会在原位置插入锚点，但把 children 挂到目标容器：

这就是 Teleport 的核心设计：组件逻辑仍在原组件树里，但真实 DOM 可以被插到别的地方。

切走组件时，不是真正卸载，而是移动到隐藏容器：

sharedContext.deactivate = (vnode: VNode) => {
  const instance = vnode.component!
  invalidateMount(instance.m)
  invalidateMount(instance.a)

  move(vnode, storageContainer, null, MoveType.LEAVE, parentSuspense)
  queuePostRenderEffect(() => {
    if (instance.da) {
      invokeArrayFns(instance.da)
    }
    const vnodeHook = vnode.props && vnode.props.onVnodeUnmounted
    if (vnodeHook) {
      invokeVNodeHook(vnodeHook, instance.parent, vnode)
    }
    instance.isDeactivated = true
  }, parentSuspense)
}

切回来时，再把缓存的 VNode / component 拿回来激活：

sharedContext.activate = (
  vnode,
  container,
  anchor,
  namespace,
  optimized,
) => {
  const instance = vnode.component!
  move(vnode, container, anchor, MoveType.ENTER, parentSuspense)
  // in case props have changed
  patch(
    instance.vnode,
    vnode,
    container,
    anchor,
    instance,
    parentSuspense,
    namespace,
    vnode.slotScopeIds,
    optimized,
  )
  queuePostRenderEffect(() => {
    instance.isDeactivated = false
    if (instance.a) {
      invokeArrayFns(instance.a)
    }
  }, parentSuspense)
}

所以 KeepAlive 的本质不是“重新渲染更快”，而是：

缓存组件实例和子树，切换时移动和激活，而不是销毁再创建。

Suspense：等待异步依赖并切换 fallback

Suspense 也通过特殊标记接入 renderer：

// Suspense exposes a component-like API, and is treated like a component
// in the compiler, but internally it's a special built-in type that hooks
// directly into the renderer.

  name: 'Suspense',
  // In order to make Suspense tree-shakable, we need to avoid importing it

  // internals.

它会创建一个隐藏容器，用来先挂载主内容；如果主内容存在异步依赖，就展示 fallback。等异步依赖解决后，再切换到主内容。

这说明 Suspense 的难点不是“显示 loading”，而是维护一个边界：

主内容是否已经准备好
异步依赖数量是否归零
fallback 当前是否显示
父级 Suspense 是否也在等待

这些状态都放在 SuspenseBoundary 里。

三者的共同设计

这三个内置组件都不是纯用户态组件，它们都和 renderer 有特殊协作：

组件 特殊点
Teleport 自己决定 children 挂载到哪个容器
KeepAlive 自己决定组件是卸载还是缓存移动
Suspense 自己决定主内容和 fallback 的切换时机

它们共同体现了一个设计：

对外保持组件 API，对内通过 renderer internals 获得底层控制权。

这样用户仍然用声明式组件写法：

<Teleport to="body" />
<KeepAlive />
<Suspense />

但运行时可以在 patch、move、unmount 这些底层动作上做特殊处理。

小结

  1. Teleport 让组件逻辑位置和 DOM 挂载位置解耦。
  2. KeepAlive 缓存组件实例和子树，切换时移动而不是销毁。
  3. Suspense 用 boundary 管理异步依赖和 fallback 切换。
  4. 三者都通过特殊标记和 renderer internals 接入渲染器。
  5. 这类内置组件的设计重点是：对外像组件，对内深度参与 renderer 流程。
