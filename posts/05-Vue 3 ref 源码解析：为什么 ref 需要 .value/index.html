Vue 3 ref 源码解析：为什么 ref 需要 .value

发表于2026|更新于2026|Vue框架及周边库
|字数总计:3.2k|阅读时长:14分钟

源码说明：本文分析的源码基于 vue@3.5.21，对应官方仓库为 vuejs/core，本文所在学习仓库为 XY0987/vue_ori_learning。

前言：前几篇我们看了 reactive 如何通过 Proxy 代理对象。可是 JavaScript 的基本类型，比如 number、string，没法被 Proxy 直接拦截属性读写。ref 的核心价值就是给这些值包一层对象，把响应式入口集中到 .value 上。

先给结论

ref 和 reactive 的响应式模型不一样：

API 响应式入口 依赖存在哪里 适合处理
reactive 对象属性的 get/set targetMap -> target -> key -> Dep 对象、数组、集合类型
ref .value 的 getter/setter ref 实例自己的 dep 基本类型，也可以包对象

所以 ref 必须通过 .value 读写，不是语法上的“麻烦”，而是它建立响应式拦截点的方式。

为什么 ref 需要 .value

先看 Ref 接口：

export interface Ref<T = any, S = T> {
  // ref 的响应式入口集中在 .value 上：读取 .value 收集依赖，写入 .value 触发依赖。
  get value(): T
  set value(_: S)
  /**
   * Type differentiator only.
   * We need this to be in public d.ts but don't want it to show up in IDE
   * autocomplete, so we use a private Symbol instead.
   */
  [RefSymbol]: true
}

reactive 依赖的是 Proxy 拦截对象属性：

state.count
state.count = 1

但基本类型没有属性读写过程，不能这样代理：

let count = 1
// 没有办法用 Proxy 拦截 count 这个变量本身的读取和赋值

所以 Vue 用对象包装一层：

const count = ref(1)

count.value      // getter：收集依赖
count.value = 2  // setter：触发依赖

我的理解是：.value 就是 Vue 给基本类型创造出来的“可拦截属性”。

ref 入口：创建 RefImpl

ref 的运行时入口很简单：

// 类型重载的目的是为了给用户更好的类型提示。
// 运行时 ref 只做一件事：创建一个围绕 .value 的响应式容器。
export function ref<T>(
  value: T,
): [T] extends [Ref] ? IfAny<T, Ref<T>, T> : Ref<UnwrapRef<T>, UnwrapRef<T> | T>
export function ref<T = any>(): Ref<T | undefined>
export function ref(value?: unknown) {
  return createRef(value, false)
}

createRef 里有一个小细节：如果传入的已经是 ref，就直接返回。

function createRef(rawValue: unknown, shallow: boolean) {
  // ref(refValue) 直接返回原 ref，避免重复包裹导致 .value 层级变深。
  if (isRef(rawValue)) {
    return rawValue
  }
  return new RefImpl(rawValue, shallow)
}

这避免了这种尴尬情况：

const a = ref(1)
const b = ref(a)

// Vue 不会让你变成 b.value.value
// 而是直接复用 a

RefImpl：ref 的核心实现

RefImpl 是 ref 真正的实现类。

class RefImpl<T = any> {
  // _value 是对外读取的值；如果传入对象，非 shallow ref 会把它转成 reactive 代理。
  _value: T
  // _rawValue 保存原始值，用于 set 时和新值做变化比较。
  private _rawValue: T

  // ref 只围绕 .value 这一处建立依赖，因此每个 ref 自带一个 Dep 即可。
  dep: Dep = new Dep()

  public readonly [ReactiveFlags.IS_REF] = true
  public readonly [ReactiveFlags.IS_SHALLOW]: boolean = false

  constructor(value: T, isShallow: boolean) {
    this._rawValue = isShallow ? value : toRaw(value)
    // 非 shallow ref 在持有对象时，会把对象转成 reactive，保证 value 内部属性仍然响应式。
    this._value = isShallow ? value : toReactive(value)
    this[ReactiveFlags.IS_SHALLOW] = isShallow
  }

  get value() {
    // 读取 .value 时收集依赖。和 reactive 的 target/key 模型不同，ref 的依赖直接挂在自身 dep 上。
    if (__DEV__) {
      this.dep.track({
        target: this,
        type: TrackOpTypes.GET,
        key: 'value',
      })
    } else {
      this.dep.track()
    }
    return this._value
  }

  set value(newValue) {
    const oldValue = this._rawValue
    // shallowRef、shallow/readonly 新值都直接保存；普通 ref 则比较原始值，并在需要时转 reactive。
    const useDirectValue =
      this[ReactiveFlags.IS_SHALLOW] ||
      isShallow(newValue) ||
      isReadonly(newValue)
    newValue = useDirectValue ? newValue : toRaw(newValue)
    if (hasChanged(newValue, oldValue)) {
      this._rawValue = newValue
      this._value = useDirectValue ? newValue : toReactive(newValue)
      if (__DEV__) {
        this.dep.trigger({
          target: this,
          type: TriggerOpTypes.SET,
          key: 'value',
          newValue,
          oldValue,
        })
      } else {
        this.dep.trigger()
      }
    }
  }
}

这里重点看三个字段：

字段 作用
_value 对外读取的值，可能是 reactive 代理
_rawValue 原始值，用于判断新旧值是否变化
dep 当前 ref 自己的依赖容器

reactive 的依赖存在全局 targetMap 里，而 ref 的依赖直接存在自己的 dep 上。原因也很简单：ref 只追踪 .value 这一处，不需要再按 target/key 分层。

get value：读取时收集依赖

get value 负责收集依赖：

  get value() {
    // 读取 .value 时收集依赖。和 reactive 的 target/key 模型不同，ref 的依赖直接挂在自身 dep 上。
    if (__DEV__) {
      this.dep.track({
        target: this,
        type: TrackOpTypes.GET,
        key: 'value',
      })
    } else {
      this.dep.track()
    }
    return this._value
  }

这和 reactive 的 baseHandlers.get 很像，只是入口不同：

reactive:
  proxy.foo -> get handler -> track(target, GET, 'foo')

ref:
  ref.value -> get value -> this.dep.track()

所以在 effect 中读取 count.value，当前 effect 就会被收集到这个 ref 的 dep 里。

const count = ref(0)

effect(() => {
  console.log(count.value)
})

依赖关系可以理解成：

countRef.dep ──► 当前 effect

set value：写入时触发依赖

set value 负责判断变化并触发依赖：

  set value(newValue) {
    const oldValue = this._rawValue
    // shallowRef、shallow/readonly 新值都直接保存；普通 ref 则比较原始值，并在需要时转 reactive。
    const useDirectValue =
      this[ReactiveFlags.IS_SHALLOW] ||
      isShallow(newValue) ||
      isReadonly(newValue)
    newValue = useDirectValue ? newValue : toRaw(newValue)
    if (hasChanged(newValue, oldValue)) {
      this._rawValue = newValue
      this._value = useDirectValue ? newValue : toReactive(newValue)
      if (__DEV__) {
        this.dep.trigger({
          target: this,
          type: TriggerOpTypes.SET,
          key: 'value',
          newValue,
          oldValue,
        })
      } else {
        this.dep.trigger()
      }
    }
  }

这里有几个关键点：

  1. 用 _rawValue 和新值比较，避免代理对象和原始对象混用导致误判。
  2. 值真的变了才触发依赖。
  3. 普通 ref 如果接收对象，会通过 toReactive 转成响应式对象。
  4. shallowRef 不会深层转 reactive。

所以：

const count = ref(0)
count.value = 0 // 不触发
count.value = 1 // 触发

ref 包对象时，内部属性也会响应式吗

会，但要分清两层依赖。

const state = ref({ count: 0 })

普通 ref 在构造时会执行：

  constructor(value: T, isShallow: boolean) {
    this._rawValue = isShallow ? value : toRaw(value)
    // 非 shallow ref 在持有对象时，会把对象转成 reactive，保证 value 内部属性仍然响应式。
    this._value = isShallow ? value : toReactive(value)
    this[ReactiveFlags.IS_SHALLOW] = isShallow
  }

也就是说，state.value 是一个 reactive 对象。

因此有两种更新：

const state = ref({ count: 0 })

effect(() => {
  console.log(state.value.count)
})

state.value = { count: 1 } // 触发 ref 的 .value 依赖
state.value.count++       // 触发 reactive 对象 count 属性的依赖

可以这样理解：

state.value = 新对象
  │
  └─ 触发 ref 层 dep

state.value.count++
  │
  └─ 触发 reactive 对象内部 count 的 dep

shallowRef 和 triggerRef

shallowRef 只追踪 .value 本身，不会把对象内部转成 reactive。

export function shallowRef<T>(
  value: T,
): Ref extends T
  ? T extends Ref
    ? IfAny<T, ShallowRef<T>, T>
    : ShallowRef<T>
  : ShallowRef<T>
export function shallowRef<T = any>(): ShallowRef<T | undefined>
export function shallowRef(value?: unknown) {
  return createRef(value, true)
}

所以：

const state = shallowRef({ count: 0 })

effect(() => {
  console.log(state.value.count)
})

state.value.count++       // 不触发，因为内部对象不是 reactive
state.value = { count: 1 } // 触发，因为 .value 引用变了

如果你确实修改了内部属性，又想手动通知依赖，可以用 triggerRef：

export function triggerRef(ref: Ref): void {
  // triggerRef 主要配合 shallowRef 使用：内部深层属性被改了，但 .value 引用没变时，可手动触发依赖。
  // ref may be an instance of ObjectRefImpl
  if ((ref as unknown as RefImpl).dep) {
    if (__DEV__) {
      ;(ref as unknown as RefImpl).dep.trigger({
        target: ref,
        type: TriggerOpTypes.SET,
        key: 'value',
        newValue: (ref as unknown as RefImpl)._value,
      })
    } else {
      ;(ref as unknown as RefImpl).dep.trigger()
    }
  }
}

这也是 shallowRef 的典型使用方式：你自己负责内部对象的更新策略，必要时手动触发。

proxyRefs：为什么 setup 返回的 ref 可以少写 .value

proxyRefs 用一个代理做浅层自动解包。

const shallowUnwrapHandlers: ProxyHandler<any> = {
  // 读取属性时浅层自动解包 ref，常用于 setup 返回对象，让模板/实例访问时不用写 .value。
  get: (target, key, receiver) =>
    key === ReactiveFlags.RAW
      ? target
      : unref(Reflect.get(target, key, receiver)),
  set: (target, key, value, receiver) => {
    const oldValue = target[key]
    // 原属性是 ref、新值不是 ref 时，保持 ref 容器不变，只更新 oldValue.value。
    if (isRef(oldValue) && !isRef(value)) {
      oldValue.value = value
      return true
    } else {
      return Reflect.set(target, key, value, receiver)
    }
  },
}

/**
 * Returns a proxy for the given object that shallowly unwraps properties that
 * are refs. If the object already is reactive, it's returned as-is. If not, a
 * new reactive proxy is created.
 *
 * @param objectWithRefs - Either an already-reactive object or a simple object
 * that contains refs.
 */
export function proxyRefs<T extends object>(
  objectWithRefs: T,
): ShallowUnwrapRef<T> {
  return isReactive(objectWithRefs)
    ? (objectWithRefs as ShallowUnwrapRef<T>)
    : new Proxy(objectWithRefs, shallowUnwrapHandlers)
}

它的行为大致是：

const user = proxyRefs({ age: ref(18) })

user.age      // 自动 unref，得到 18
user.age = 20 // 等价于 ageRef.value = 20

这解释了为什么很多场景里你不用写 .value。不是 ref 本身不需要 .value，而是外面又包了一层代理帮你做了自动解包。

toRef 和 toRefs：把对象属性变成 ref

toRefs 会把一个响应式对象的每个属性都转成 ref。

export function toRefs<T extends object>(object: T): ToRefs<T> {
  if (__DEV__ && !isProxy(object)) {
    warn(`toRefs() expects a reactive object but received a plain one.`)
  }
  const ret: any = isArray(object) ? new Array(object.length) : {}
  // 为每个 key 创建一个和原对象属性双向同步的 ObjectRefImpl。
  for (const key in object) {
    ret[key] = propertyToRef(object, key)
  }
  return ret
}

具体属性 ref 是 ObjectRefImpl：

class ObjectRefImpl<T extends object, K extends keyof T> {
  public readonly [ReactiveFlags.IS_REF] = true
  public _value: T[K] = undefined!

  constructor(
    private readonly _object: T,
    private readonly _key: K,
    private readonly _defaultValue?: T[K],
  ) {}

  get value() {
    // ObjectRefImpl 不自己创建 Dep，而是读原对象属性，让原对象的 reactive 依赖系统负责 track。
    const val = this._object[this._key]
    return (this._value = val === undefined ? this._defaultValue! : val)
  }

  set value(newVal) {
    // 写入 ref.value 等价于写入原对象对应属性，从而触发原对象的 reactive 更新。
    this._object[this._key] = newVal
  }

  get dep(): Dep | undefined {
    // 暴露原对象属性对应的 Dep，便于 triggerRef 等工具复用。
    return getDepFromReactive(toRaw(this._object), this._key)
  }
}

这个设计很巧妙：ObjectRefImpl 自己不创建新的 Dep，而是读写原对象属性。这样依赖仍然归属于原来的 reactive 对象属性。

const state = reactive({ count: 0 })
const count = toRef(state, 'count')

count.value++
console.log(state.count) // 1

state.count++
console.log(count.value) // 2

toRef 的入口也支持几种不同形式：

export function toRef(
  source: Record<string, any> | MaybeRef,
  key?: string,
  defaultValue?: unknown,
): Ref {
  if (isRef(source)) {
    return source
  } else if (isFunction(source)) {
    // getter 形式转成只读 ref。
    return new GetterRefImpl(source) as any
  } else if (isObject(source) && arguments.length > 1) {
    // object + key 形式创建属性 ref，和源对象属性保持同步。
    return propertyToRef(source, key!, defaultValue)
  } else {
    // 普通值转成常规 ref。
    return ref(source)
  }
}

function propertyToRef(
  source: Record<string, any>,
  key: string,
  defaultValue?: unknown,
) {
  const val = source[key]
  // 如果源属性本身已经是 ref，直接复用；否则创建 ObjectRefImpl 代理这个属性。
  return isRef(val)
    ? val
    : (new ObjectRefImpl(source, key, defaultValue) as any)
}

总结一下：

用法 结果
toRef(existingRef) 直接返回原 ref
toRef(() => props.foo) 创建只读 getter ref
toRef(state, 'foo') 创建和 state.foo 双向同步的属性 ref
toRef(1) 等价于 ref(1)

customRef：自己控制 track 和 trigger

customRef 允许用户自己决定什么时候收集依赖、什么时候触发更新。

class CustomRefImpl<T> {
  public dep: Dep

  private readonly _get: ReturnType<CustomRefFactory<T>>['get']
  private readonly _set: ReturnType<CustomRefFactory<T>>['set']

  public readonly [ReactiveFlags.IS_REF] = true

  public _value: T = undefined!

  constructor(factory: CustomRefFactory<T>) {
    const dep = (this.dep = new Dep())
    // customRef 把 track/trigger 的控制权交给用户，用户可以决定何时收集、何时触发。
    const { get, set } = factory(dep.track.bind(dep), dep.trigger.bind(dep))
    this._get = get
    this._set = set
  }

  get value() {
    return (this._value = this._get())
  }

  set value(newVal) {
    this._set(newVal)
  }
}

/**
 * Creates a customized ref with explicit control over its dependency tracking
 * and updates triggering.
 *
 * @param factory - The function that receives the `track` and `trigger` callbacks.
 * @see {@link https://vuejs.org/api/reactivity-advanced.html#customref}
 */
export function customRef<T>(factory: CustomRefFactory<T>): Ref<T> {
  return new CustomRefImpl(factory) as any
}

它常见的使用场景是防抖 ref：

function useDebouncedRef<T>(value: T, delay = 200) {
  let timer: ReturnType<typeof setTimeout>

  return customRef<T>((track, trigger) => ({
    get() {
      track()
      return value
    },
    set(newValue) {
      clearTimeout(timer)
      timer = setTimeout(() => {
        value = newValue
        trigger()
      }, delay)
    },
  }))
}

这里读取时手动 track()，写入时不立刻 trigger()，而是在防抖结束后再触发。

小结

  1. ref 通过 .value 创造可拦截的读写入口，所以基本类型也能响应式。
  2. RefImpl 自带一个 Dep，读取 .value 时 track，写入 .value 时 trigger。
  3. 普通 ref 包对象时，会把对象转成 reactive，所以对象内部属性也能响应式。
  4. shallowRef 只追踪 .value 引用变化，内部深层变化需要 triggerRef 手动触发。
  5. proxyRefs 是浅层自动解包工具，不是 ref 本身不需要 .value。
  6. toRef / toRefs 创建的是和源对象属性同步的 ref，适合解构响应式对象时保持响应式。
  7. customRef 把 track / trigger 暴露给用户，适合防抖、节流等自定义响应式策略。
